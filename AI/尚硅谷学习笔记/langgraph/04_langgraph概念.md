# LangGraph 概念

## LangChain vs LangGraph

### LangChain 的工作方式

LangChain 是直接调用大模型、传入工具——本质上是一个**调度框架**：

```
输入: prompt + 大模型 + 工具 + memory → 输出: output
```

LangChain 只是简单地对大模型进行引入，传入提示词和工具，最后输出一个结果。

### LangGraph 的升级

LangGraph 是 LangChain 的**高维升级版**：

- 输入可以是**任何数据类型**（字符串、整型、列表等），不局限于 prompt/memory/tools
- 内部通过 **State（状态）** 进行管理，所有数据放在 state 中
- 通过**节点**进行逻辑处理，节点可以完成任何功能

```
输入（任意数据类型）→ State（内部状态管理）→ 节点（逻辑处理）→ 输出
```

LangChain 只能做到大模型响应，而 LangGraph 可以把大模型响应放在**工作流**中，规范化输入输出细节，完成更复杂的事情。

---

## 核心三要素

### 1. 状态（State）

图中进行管理的数据。任何和工作流相关的数据都会存在 state 之中。

### 2. 节点（Node）

代表**计算单元**，通过与数据交互来进行数据处理：
- 从状态中提取数据传给大模型 → 大模型返回响应
- 从状态中提取数据传给外部工具 → 工具返回结果
- 任何自定义逻辑都可以在节点中实现

### 3. 边（Edge）

连接不同节点，搭建完整工作流。

---

## 工作流数据流转

```
外部输入 → [State] 存储数据
                ↓
        大模型节点 ←→ State（读取配置 / 存储响应）
                ↓
        MySQL节点 ←→ State（读取配置 / 回写结果）
                ↓
        输出节点 → 从 State 提取结果 → 外界输出
```

**每个节点都与 State 进行交互**，实现数据的读取与操作。边负责连接节点，但**数据的传递是通过 State**，而不是通过边。

> 费曼说：State 就像是一个公共工作台，每个节点（工人）从这个台子上拿材料（读取数据），加工完再放回去（写回数据）。边就像是工位之间的传送带，告诉工人下一步去哪个工作站。

---

## LangGraph 的特性

### 图结构支持
- 完全支持**图结构**：循环、嵌套、分支，图能做什么它就能做什么
- 可以**中断输出**，加入人为中断

### 为什么使用 LangGraph？

随着复杂度提升，需要把所有信息维护在 state 之中。LangGraph 能解决更复杂的事情：

| 维度 | LangChain | LangGraph |
|------|-----------|-----------|
| **复杂度** | 简单的线性调用 | 复杂工作流 |
| **状态管理** | 全靠提示词传参 | 统一 State 管理 |
| **节点** | 单一的大模型调用 | 任意节点（LLM、工具、自定义逻辑） |
| **灵活性** | 一人孤军奋战 | 多人协作，任务分解 |

## 应用场景

### 1. 复杂的多智能体系统

每个节点都可以放入大模型，多个大模型协同工作：

```
问题
 ├── 大模型A（分析层面1）
 ├── 大模型B（分析层面2）  → 汇总结果
 └── 大模型C（分析层面3）
```

比 LangChain 更高级——LangChain 是一个人孤军奋战，LangGraph 是团队协作，上下游协同配合。

### 2. 长期记忆应用

LangChain 的实现方式：把外部数据放到提示词中传入。

LangGraph 的实现方式：数据直接存储在 **State** 中，而不是在单次调用时传入。

- 想用的时候提取出来
- 不用的时候存起来
- 不同节点按需获取，不需要的记忆节点可以跳过

### 3. 人工审核工作流

工作流运行到一半时**中断**，提供人为引导和指令（如允许/不允许），恢复时携带新值继续执行。

```
工作流 → 遇到判断点 → 中断 → 人为输入（true/false）→ 恢复执行
```

### 4. 精细化控制的定制化编排

State 是很细节的东西，可以**任意提取、任意修改**。每个部分都可以放入它所需要的状态，而不是像 LangChain 把所有东西全塞在一个提示词里调用。
