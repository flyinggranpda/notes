## 2. 项目概述

### 2.1 产品需求

本次实战项目要构建一个**个人健康助理 APP**（参考 AQ 产品），核心功能：

| 功能 | 描述 | 需要的模型 |
|------|------|-----------|
| **健康问答** | 用户输入文字描述病症，返回健康建议 | 语言大模型（文字进文字出） |
| **图片解读** | 用户上传医疗报告/化验单图片，自动解读异常指标 | 多模态大模型（图文进文字出） |
| **健康档案** | 用户历史健康记录管理 | 前端 + 后端数据库（本次不涉及） |

本次课程聚焦**图片解读**功能，完成后健康问答功能只需将用户文字输入直接传给语言模型即可。

### 2.2 技术架构

```
用户 APP
    │
    ▼
Web 应用（CPU 服务器 / Flask）
    │
    ├── 文字输入 → 语言大模型服务（LLM Server / VLLM）
    │                   │
    │                   ▼  Qwen2.5-14B (4-bit 量化微调)
    │              返回健康建议
    │
    └── 图片输入 → 多模态大模型服务（VLM Server / VLLM）
                        │
                        ▼  Qwen2.5-VL-7B (微调)
                   返回图像分析结果（异常指标）
                        │
                        ▼
                   语言大模型 → 根据分析结果给出健康建议
```

**架构说明：**
1. 用户上传医疗图像 → Web 应用（Flask）转发给多模态服务
2. 多模态模型分析报告（如"白细胞偏高"）→ 返回文本结果
3. 语言模型根据分析结果给出健康建议 → 逐级返回给用户
4. 健康问答功能则更简单：文字直接进语言模型，无需多模态环节

### 2.3 技术栈

| 组件 | 技术选型 | 说明 |
|------|---------|------|
| 微调框架 | **Unsloth** | 全系列主力框架 |
| 语言大模型 | **Qwen2.5-14B-Instruct** | 微调 + 4-bit 量化 |
| 多模态大模型 | **Qwen2.5-VL-7B-Instruct** | 微调（无需量化，7B 可塞入 32G 显存） |
| 推理部署 | **VLLM** | 部署微调后的模型为服务接口 |
| 后端框架 | **Flask** | Web 服务（下次课详细讲解） |
| 医疗数据集 | **md QA2** | 医疗问答数据集（~10 万条） |
| 医疗图像 | 自定义多模态数据集 | 医疗报告图片 + 解读 |

## 4. 数据集准备

### 4.1 数据来源：md QA2

选择数据集的核心原则：**数据集类型必须与产品场景一致**。

- 我们的场景是**一问一答**（用户问 → 模型回答）
- 不能使用评测类数据（如"感冒了选 A/B/C/D"那种选择题格式）
- 选择 **md QA2**：医疗问答数据集，约 10 万条 QA 对

### 4.2 数据清洗：合并 question 与 answer

md QA2 的原始数据较为特殊 —— question 和 answer 分在两个 CSV 文件中：

**question.csv**（问题表）：
| question_id | content |
|-------------|---------|
| 1 | 头痛、恶心、肌肉痛、关节痛，全身都痛 |
| 2 | 男，67岁，右下肢肿胀疼痛 |

**answer.csv**（答案表）：
| answer_id | question_id | content |
|-----------|-------------|---------|
| 101 | 2 | 建议彩超检查，检查右下之动静脉情况，了解有无血管病变 |
| 102 | 1 | 月经14天且伴随恶心的现象，考虑怀孕的几率非常大 |

**发现的问题**：行与行不是一一对应的（question 第 1 行不一定对应 answer 第 1 行），需要通过 `question_id` 进行匹配。

### 4.3 数据合并流程

```
第1步：读取 question.csv 和 answer.csv
第2步：将两个 CSV 转为字典，以 ID 为 key
第3步：遍历 question，在 answer 字典中查找对应的 answer_id
第4步：形成 question → answer 的键值对
第5步：转换为大模型训练格式（ShareGPT 格式）
```

**核心代码逻辑**：

```python
import csv

# 第1步：读 question.csv 和 answer.csv
# 第2步：转字典，key = ID, value = content
question_dict = {row['question_id']: row['content']
                 for row in csv.DictReader(open('question.csv'))}
answer_dict = {}
for row in csv.DictReader(open('answer.csv')):
    # answer 表有 answer_id, question_id, content 三个字段
    qid = row['question_id']
    if qid not in answer_dict:
        answer_dict[qid] = []
    answer_dict[qid].append(row['content'])

# 第3步：按 question_id 匹配
pairs = []
for qid, question in question_dict.items():
    if qid in answer_dict:
        for answer in answer_dict[qid]:
            pairs.append({"question": question, "answer": answer})

# 第4步：转成大模型训练格式
dataset = []
for q, a in pairs:
    dataset.append({
        "conversations": [
            {"from": "user", "value": q},
            {"from": "assistant", "value": a}
        ]
    })
```

### 4.4 最终数据集格式（ShareGPT）

```json
{
  "conversations": [
    {
      "from": "user",
      "value": "头痛、恶心、肌肉痛、关节痛，全身都痛"
    },
    {
      "from": "assistant",
      "value": "建议您尽快就医，进行血常规检查..."
    }
  ]
}
```

> **费曼说**：数据清洗没有固定流程，核心思路是"现状 vs 目标"——搞清你手头的数据长什么样（现状），搞清大模型需要什么格式（目标），然后写脚本跨过这条鸿沟。每种数据集都不同，每次都要自己洗。

### 4.5 多数据集微调的建议

| 方式 | 评价 | 推荐 |
|------|------|------|
| 多次微调（先调 A 再调 B） | 后一次会覆盖前一次的改动 | **不推荐** |
| 合并数据集一次微调 | 一次性把曲线掰到位 | **强烈推荐** |

> **微调的曲线拟合本质**：大模型训练本质上是用大量低次线性函数拟合高维复杂的知识空间。微调就是在通用模型曲线的基础上，用新数据（蓝色点）在某个局部把曲线掰向期望的方向。如果多次掰，第二次会覆盖第一次的效果；一次性把所有数据喂进去效果最好。

## 5. 语言大模型微调（Qwen2.5-14B + 4-bit 量化）

### 5.1 量化必要性

Qwen2.5-14B 在 FP16 精度下需约 28GB 显存，加上训练开销 32G 显存无法承载。因此需要：

1. **选择量化的基座模型**（BNB 4-bit 版本）
2. **保持 4-bit 量化进行微调**
3. **保存时强制合并为 4-bit 格式**

### 5.2 量化的四个关键条件

| 条件 | 说明 |
|------|------|
| **① 基座模型是量化版本** | 必须使用 `-BNB-4bit` 结尾的模型 |
| **② load_in_4bit=True** | 加载时启用 4-bit |
| **③ 保存目录名以 `-BNB-4bit` 结尾** | 否则不会量化，且无提示 |
| **④ save_method = merged_4bit** | 强制保存为 4-bit 格式 |

```python
from unsloth import FastLanguageModel

# 条件① 条件②：加载量化的基座模型
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-14B-Instruct-BNB-4bit",
    load_in_4bit=True,  # 条件②
)

# 配置 LoRA
model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
)

# 训练
trainer.train()

# 条件③ 条件④：保存
model.save_pretrained(
    "Qwen2.5-14B-finetuned-BNB-4bit",  # 条件③：目录名以 -BNB-4bit 结尾
    save_method="merged_4bit",          # 条件④
)
```

量化后的 14B 模型在 32G 显存上勉强跑动，显存占用约 30G/32G，基本吃满。

### 5.3 训练参数

```python
from transformers import TrainingArguments

training_args = TrainingArguments(
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,     # 等效 batch_size = 8
    max_steps=60,                      # 可调大（如 80）增强效果
    learning_rate=2e-4,
    lr_scheduler_type="linear",
    warmup_steps=5,                    # 前 5 步从 0 逐渐增大 lr
    optim="adamw_8bit",                # 8-bit 优化器省显存
)
```

**学习率调度过程**：
```
学习率曲线：
          ▲
          │    ┌─ 逐步上升（warmup）
          │   ╱
          │  ╱
          │ ╱  ── 达到峰值后线性下降
          │╱                 ↘
          │                    ↘
          └──────────────────────────► 步数
               warmup=5步     max_steps=60
```

学习率不是固定值：前 5 步从 0 逐渐增大到设定值，之后逐渐减小。这是因为模型越接近目标，步幅需要越小，防止"过站"。

### 5.4 大语言模型微调三步法

```
第1步：选择量化的基座模型
第2步：准备并格式化数据集（ShareGPT 格式）
第3步：使用 Unsloth 微调 → 保存 → VLLM 部署
```

## 6. 多模态大模型微调（Qwen2.5-VL-7B）

### 6.1 与语言模型微调的差异

| 维度 | 语言模型（LLM） | 多模态模型（VLM） |
|------|----------------|------------------|
| 基座模型 | Qwen2.5-14B-Instruct | Qwen2.5-VL-7B-Instruct |
| 是否需要量化 | **是**（14B 太大，必须 4-bit） | **否**（7B 可塞入 32G） |
| 数据集格式 | 纯文字问答 | 图片 + 文字对 |
| 依赖 | torch + transformers | **需额外装 torchvision** |
| VLLM 版本 | 最新版即可 | 需特定版本（0.10.0） |

### 6.2 多模态数据集准备

多模态数据集使用 Hugging Face 的 `load_dataset` 加载，数据目录结构必须严格按规范：

```
dataset_image/
  └── train/                    # 子目录名必须叫 train
      ├── image_001.jpg
      ├── image_002.jpg
      ├── ...
      └── metadata.jsonl        # 元数据文件，文件名固定
```

**metadata.jsonl 格式**（每行一个合法的 JSON）：

```json
{"file_name": "image_001.jpg", "addition_features": "解读这一份报告，一句话解释指定异常指标"}
{"file_name": "image_002.jpg", "addition_features": "分析这份化验单，指出异常项目"}
```

**关键规范**：
- 目录结构：根目录下必须有 `train` 子目录（硬编码）
- 元数据文件名必须为 `metadata.jsonl` 或 `metadata.csv`（硬编码）
- `file_name` 字段对应图片文件名
- `addition_features` 字段（字段名可自定义）是期望输出的文本

**多模态数据加载代码**：

```python
from datasets import load_dataset

dataset = load_dataset(
    "imagefolder",            # 数据集类型
    data_dir="dataset_image", # 数据目录
    split="train",
)
```

```python
# 数据预处理
def process_sample(example):
    return {
        "image": example["image"],
        "text": example["addition_features"],
    }

dataset = dataset.map(process_sample)
```

### 6.3 多模态微调（无需量化）

```python
from unsloth import FastLanguageModel

# 加载多模态基座模型
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-VL-7B-Instruct",
    # 不需要 load_in_4bit，7B 的 FP16 约 14G 显存
)

# 配置 LoRA
model = FastLanguageModel.get_peft_model(model, r=16)

# 训练
trainer = Trainer(
    model=model,
    args=TrainingArguments(
        per_device_train_batch_size=2,
        gradient_accumulation_steps=4,
        max_steps=60,
        learning_rate=2e-4,
    ),
    train_dataset=dataset,
)
trainer.train()

# 保存（不量化，直接保存完整精度）
model.save_pretrained("Qwen2.5-VL-7B-finetuned")
```

多模态模型不需要量化，保存也很慢（完整精度文件较大）。

### 7.3 多模态图片处理的坑

| 问题 | 原因 | 解决 |
|------|------|------|
| 图片超上下文 | 大图片占用过多 token | 用 `thumbnail` 缩小到最长边 1024 像素 |
| OpenAI 文档中的 image 类型参数无效 | VLLM 版本未跟上 OpenAI API 更新 | 用 `image_url` 而非 `input_image` |
| base64 编码 + 大图片 | 未缩放直接编码会超上下文 | 先缩放再编码 |

### 7.4 VLLM 的版本兼容性

| 场景 | VLLM 版本 | 说明 |
|------|-----------|------|
| 语言模型推理 | 最新版 | 兼容性好，无问题 |
| 多模态模型推理 | **0.10.0** | 新版有 bug，无法加载多模态模型 |
| 多模态 + 语言混合 | 建议分别建虚拟环境 | 不同版本的 VLLM 需要隔离 |

## 8. 避坑指南

### 8.1 环境配置

| 问题 | 原因 | 解决 |
|------|------|------|
| torchvision 报错 | 版本与 torch 不对应 | 查 torchvision 官方版本对应表，`pip show torch` 后再装对应版本 |
| Unsloth 安装失败 | CUDA 版本不匹配 | 在 PyTorch 官网选对应 CUDA 版本的命令安装 |
| Transformer 崩溃 | 版本过高不兼容 | 降级到 5.5 版本 |
| VLLM 报 index out of range | URL 末尾斜杠缺失 | `base_url` 以 `/v1` 结尾，不要省略斜杠 |

### 8.2 量化

| 问题 | 原因 | 解决 |
|------|------|------|
| 保存未量化 | 缺少条件 | 必须同时满足 4 个条件：基座量化 + load_in_4bit + 目录名后缀 + save_method |
| 量化后精度损失 | 4-bit 量化的固有问题 | 权衡：显存不够时量化是唯一方案 |
| 显存溢出 | 上下文太长 | 限制 `max-model-len` 到 32K |

### 8.3 微调

| 问题 | 原因 | 解决 |
|------|------|------|
| 多模态保存慢 | 未量化，完整精度文件大 | 等待即可（无量化参数时正常现象） |
| Notebook 显存不释放 | Jupyter session 持续占显存 | 重启 kernel 或重启服务器 |
| 效果不好 | 数据质量不够/步数不够 | 先调大 max_steps；仍不行则检查数据质量 |

### 9.3 关键经验

1. **量化是硬塞的手段** —— 如果模型能塞进显存，就不要量化（损失精度）
2. **数据清洗最关键** —— 每次数据集都不一样，写脚本跨越"现状 vs 目标"的鸿沟
3. **微调三步法**：选基座 → 准备数据 → 微调+部署
4. **多模态 VS 语言微调**：只有数据集格式和 torchvision 依赖不同，其他完全一致
5. **环境坑多于代码坑** —— VLLM 版本、torchvision 版本、transformers 版本都需要精确对应
