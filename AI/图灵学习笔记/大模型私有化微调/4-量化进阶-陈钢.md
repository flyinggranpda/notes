## 2. 核心概念图谱

### 2.1 算力相关概念

| 中文术语 | 英文缩写 | 通俗解释 |
|---------|---------|---------|
| 每秒整数运算次数 | TOPS (Tera Operations Per Second) | 一秒钟能算多少次**整数**运算，CPU 厂商（Intel/微软）主推的指标 |
| 每秒浮点运算次数 | TFLOPS (Tera Floating-point OPS) | 一秒钟能算多少次**浮点**运算，**GPU 厂商真正关心的指标** |
| AIPC | AI PC | 微软定义：NPU/GPU 算力 ≥ 40 TOPS 的 PC，可贴标签 |
| 前向传播 | Forward | 输入数据经过模型算出预测值的过程（推理） |
| 反向传播 | Backward | 根据预测值与真实值的误差更新参数的过程（训练） |
| 参数量 FLOPS | MAC (Multiply-Accumulate) | 矩阵相乘的次数 |
| 浮点运算量 | FLOPS (FLoating-point OPS) | 结合矩阵乘以后实际浮点计算的次数 |

### 2.2 量化精度概念

| 精度 | 全称 | 每参数占 | 说明 |
|------|------|---------|------|
| FP32 | Float 32 | 4 bytes | 标准单精度浮点数（CPU 原生） |
| FP16 | Float 16 | 2 bytes | 半精度浮点数（NVIDIA） |
| BF16 | Brain Float 16 | 2 bytes | Google Brain 发明，**范围更大但精度更低** |
| TF32 | Tensor Float 32 | 4 bytes | 也是 32 位，但精度比 FP32 低，范围不变 |
| INT8 | Integer 8 | 1 byte | 8 位整数，常用于推理量化 |
| INT4 | Integer 4 | 0.5 byte | 4 位整数，常用于 QLoRA 微调 |
| NF4 | Normal Float 4 | 0.5 byte | **按正态分布分配**的 4bit 量化，QLoRA 的创新点 |

### 2.3 量化方法概念

| 方法 | 全称 | 核心思路 |
|------|------|---------|
| **PTQ** | Post-Training Quantization | 训练**完成之后**再做量化，简单兼容广 |
| **QAT** | Quantization-Aware Training | **边训练边量化**，精度更高但训练变慢 |
| **GPTQ** | GPT Post-Training Quantization | PTQ 的优化版，**分组并行量化**，速度+精度都提升 |
| **AWQ** | Activation-Aware Weight Quantization | 保护最重要的 1% 权重用高精度，其余用低精度 |
| **QLoRA** | Quantized LoRA | **QAT + LoRA**，Unsloth 默认方案，load_in_4bit |

### 2.4 对称 vs 非对称量化

| 类型 | 图示 | 误差 | 计算复杂度 |
|------|------|------|-----------|
| **对称量化** | 零在中间，正负对称 | 较大（0.03）| 简单 |
| **非对称量化** | 统一取 min~max | **更小（0.007）** | 稍微复杂 |

### 2.5 GGUF 文件命名规则

```
例：llama-2-13b-finetune-Q4_K_M.gguf
      ↑       ↑    ↑        ↑
   模型名   参数量  微调情况  量化规格

Q4_K_M 含义：
  Q    = 量化（Quantized）
  4    = 目标 4 bit
  K    = 分组量化
  M    = 中号（类似衣服尺码：XS/S/M/L/XL）
```

## 3. 技术原理 / 流程拆解

### 3.1 算力计算

**三个需要计算算力的场景：**

```
场景一：训练需要多久？
  已知数据集 5 万张图片，batch_size=100，epoch=20
  每批 100 张需 0.2 秒
  每轮 = 50000/100 × 0.2 = 100 秒 ≈ 1.67 分钟
  总时间 = 1.67 × 20 = 33.4 分钟

场景二：买新卡能快多少？
  新卡算力 / 旧卡算力 = 提速倍数
  旧卡 3 小时，新卡算力是旧卡 2 倍 → 1.5 小时

场景三：换模型要多久？
  用工具计算两个模型的 FLOPS
  旧模型 FLOPS=360G，耗时 1 小时
  新模型 FLOPS=1700G
  新耗时 = 1 × (1700/360) ≈ 4.7 小时 ≈ 5 小时
```

**TOPS 与 TFLOPS 的区别：**

```
TOPS  （整数运算）→ CPU 厂商（Intel/微软）主推
TFLOPS（浮点运算）→ GPU 厂商（NVIDIA）主推

为什么 CPU 主推 TOPS？
  因为 CPU 不擅长浮点运算，提 TFLOPS 太难看
  GPU 天生为游戏设计（弹道计算 = 浮点运算）

为什么我们看 TFLOPS？
  因为神经网络参数都是浮点数（0.xxx、1.xxx）
  微调和推理主要做浮点运算
```

**算力查询工具：**
```bash
pip install fvcore  # Facebook 的算力计算库

# 计算模型的 FLOPS
from fvcore.nn import FlopCountAnalysis

# 需要：模型名、batch_size、输入尺寸（文本是 seq_len，图像是 H×W）
flops = FlopCountAnalysis(model, input)
print(flops.total())  # 输出 Forward/Backward 的 MAC 和 FLOPS
```

**工具输出 4 个值：**
```
Forward MAC         → 前向传播的矩阵相乘次数
Forward FLOPS       → 前向传播的浮点运算量   ← 微调用这个！
Backward MAC        → 前向+反向的矩阵相乘次数
Backward FLOPS      → 前向+反向的浮点运算量
```

**为什么微调只看 Forward FLOPS？**
> 老师原话："因为我们只调新加上的 LoRA 适配器，不是在调原模型。原始基座模型对它来说只是在做预测，我们不会反向传播去改它。"

### 3.2 浮点数存储原理

```
FP32（32 位浮点数）的存储格式：

[ S ] [ E E E E E E E E ] [ M M M ... M M M ]
  1          8                  23
符号位     指数部分           尾数部分

值 = (-1)^S × 2^(E-127) × (1 + M)

例如：
  二进制：0 01111100 01000000000000000000000
  S=0（正数）
  E=124 → 2^(124-127) = 2^(-3) = 0.125
  M=0.25 → 1.25
  值 = 0.125 × 1.25 = 0.15625
```

**各种精度的对比：**

```
FP32: S(1) + E(8) + M(23)  → 范围大，精度高
FP16: S(1) + E(5) + M(10)  → 范围小，精度低
BF16: S(1) + E(8) + M(7)   → 范围=FP32，精度=FP16 的 1/3（Google Brain 发明）
TF32: S(1) + E(8) + M(10)  → 范围=FP32，精度=FP16（NVIDIA 发明）

BF16 和 TF32 的共同目标：
  在不缩小范围的前提下降低精度
  因为大模型参数不需要那么精确，但需要能表示大范围的数
```

### 3.3 量化原理（对称量化）

```
原始矩阵中的值：[5.47, -7.59, 18.0, ...]

第一步：找范围
  max = 18.0, min = -7.59
  全长 = 18.0 + 7.59 = 25.59（对称：两个方向取较大者 → 18.0）

第二步：算刻度（scale）
  目标 INT8（127 个格子）
  scale = 18.0 / 127 = 0.1417

第三步：量化
  5.47 / 0.1417 = 38.6 → 四舍五入 = 39
  -7.59 / 0.1417 = -53.6 → 四舍五入 = -54
  18.0 / 0.1417 = 127.0 → 127

第四步：反量化（还原）
  39 × 0.1417 = 5.526    （原值 5.47，误差 0.056）
  54 × 0.1417 = 7.652    （原值 -7.59，误差 0.062）
  127 × 0.1417 = 18.0    （原值 18.0，无误差）

结论：量化后每个值从 4 字节变 1 字节 → 省 75% 显存
      代价是约 0.03~0.06 的精度损失
```

### 3.4 对称 vs 非对称量化

```
对称量化：
        负方向       零       正方向
  min=-7.59 ......|..........|max=18.0
                 零对称中心
  只用正方向算格子：18.0/127=0.1417
  误差：5.47→5.44（误差 0.03）

非对称量化：
  min=-7.59 ......|..........|max=18.0
  全长 = 18.0 + 7.59 = 25.59
  格子 = 25.59 / 255 = 0.1004
  误差：5.47→5.463（误差 0.007）

非对称量化误差更小（0.03 vs 0.007），但计算稍复杂
```

### 3.5 训练时量化的难点

```
训练过程中，权重值每步都在变化！

问题：
  第一步：范围 -7.59 ~ 18.0，scale=0.1417
  第二步：某个权重变成 19.5，超出范围！
  → 所有量化值作废 → 重算 scale → 全部重新量化 → 极其费时

解决方案：
  方法一（PTQ）：等训练完全结束，权重不再变化时再做量化
  方法二（QAT）：训练时就加量化层，让反向传播也考虑量化误差
```

### 3.6 四种量化方法详解

```
量化方法谱系：

训练后量化（PTQ）
  ├── 原始 PTQ：训练完直接量化，简单兼容广
  ├── GPTQ：PTQ 优化版，分组并行 + 二阶近似，精度更好
  └── AWQ：保护 1% 重要权重用高精度，其余用低精度

训练中量化（QAT）
  └── 边训练边量化，精度最高但训练慢
      └── QLoRA：QAT + LoRA（Unsloth 默认）
```

**PTQ（Post-Training Quantization）：**
```
流程：训练完成 → 权重固定 → 量化权重 → 得到小模型

优点：
  ✅ 不用改训练代码
  ✅ 兼容模型多
  ✅ 流程简单（两个脱钩的步骤）
缺点：
  ❌ 精度比 QAT 低
```

**GPTQ（GPT Post-Training Quantization）：**
```
PTQ 的优化版，论文整合了 4 篇前人工作：
  1. OBD（1990）：直接把不重要参数设为 0（剪枝）
  2. OBS（1992）：剪枝后重新训练补偿精度
  3. OBC（2022）：优化上面两步的计算复杂度
  4. 分组并行量化：矩阵分成多组同时量化

核心创新：
  → 把矩阵分成多组（如 3×3 分成 3 行）
  → 每组独立算 scale，可以并行计算
  → 分组更细 → 精度更高
  → 并行 → 速度更快
代价：需要存多个 scale 值（原来 1 个 → 3 个）
```

**AWQ（Activation-Aware Weight Quantization）：**
```
核心洞察：所有权重不是同等重要的
  
  保护最重要的 1% 权重使用 FP16
  其余 99% 使用 INT3/INT4

怎么判断重要性？
  → 通过 Activation（激活值）的大小判断
  → 激活值大的权重更重要

效果：
  → 只有 1% 用高精度 → 整体压缩比极高
  → 精度损失极小
  
典型应用：DeepSeek 的 1.58bit 量化
  → 不同矩阵用不同的量化精度
  → 有的 4bit，有的 2bit，有的 1bit
  → 综合下来平均 1.58bit
```

**QAT（Quantization-Aware Training）：**
```
流程：训练中就在模型里插入量化层
      前向传播时经过量化层
      反向传播时量化层也会被更新

          ┌─────────────┐
 输入 →    │ 激活函数 → 量化层 → 归一化 →    → 输出
          └─────────────┘
                  ↑
          多出来的线性量化层

优点：精度最高（量化参数也能被 loss 优化）
缺点：训练变慢，模型变复杂
```

**QLoRA（Quantized LoRA）：两个创新点**

```
创新点 1：NF4（Normal Float 4）
  INT4：0~15 平均分布（每个值间隔一样）
  NF4：按照正态分布，中间密两边疏
  → 大多数模型参数集中在中间范围
  → NF4 让中间精度更高 → 整体误差更小

创新点 2：双重量化
  第一层：对权重做 4bit 量化
  第二层：对 scale 值也做量化
  → 进一步减小模型体积
```

### 3.7 四种精度设置档位

```python
# Unsloth 中的四种选择
from unsloth import FastLanguageModel

# 档位 1：不量化（精度最高，显存最大）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="...",
    load_in_4bit=False,  # 默认 FP16
)

# 档位 2：4bit 量化（QLoRA，平衡）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="...",
    load_in_4bit=True,   # QAT + INT4
)

# 档位 3：在训练后做 PTQ（进一步压缩）
# 先用 QAT 微调，再用 TorchTune 做 PTQ
```

**场景选择（老师原话）：**
```
能不能忍受现在的训练速度？
  → 能忍受 → load_in_4bit=False（精度优先）
  → 想快/显存不够 → load_in_4bit=True（速度优先）
  一般默认用 True 就好
```

### 4.2 案例二：手动算对称量化 vs 非对称量化

- **教学目的**：亲手算一遍，理解量化误差的来源
- **要回答的核心问题**：量化到底损失了多少精度？

```python
# 对称量化
max_val = 18.0
scale_sym = 18.0 / 127         # = 0.1417
q = round(5.47 / scale_sym)    # = 39
deq = q * scale_sym             # = 5.526
error_sym = abs(5.47 - 5.526)  # = 0.056

# 非对称量化
min_val = -7.59
full_range = 18.0 + 7.59        # = 25.59
scale_asym = full_range / 255   # = 0.1004
value = 5.47 + 7.59             # = 13.06（偏移到 0 开始）
q = round(value / scale_asym)   # = 130
deq = q * scale_asym - 7.59     # = 5.463
error_asym = abs(5.47 - 5.463)  # = 0.007 ✅ 更小
```

### 4.4 GGUF 文件格式解读

**GGUF 不是量化方法，是文件格式（常见误区纠正）：**

```
常见错误说法："我用 GGUF 量化了这个模型"
正确的说法："我把模型导出成 GGUF 格式，用了 Q4_K_M 量化规格"

GGUF 格式命名规则：
  Q      = 量化
  数字   = 目标 bit 数
  字母   = 尺码（XS/S/M/L/XL），越大质量越高同 bit 内
  K      = 分组量化

例：Q4_K_M = 4bit 分组量化，中号（平衡）
    Q2_XS   = 2bit 分组量化，极小号（极致压缩）
    Q8_0    = 8bit 量化（几乎无损）
```

## 5. 避坑指南（隐性知识提取）

### 5.1 算力计算避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| 以为 TOPS 和 TFLOPS 一样 | 整数 vs 浮点运算 | 做微调看 TFLOPS，TOPS 是 CPU 厂商的指标 |
| 算训练时间时用了 Backward FLOPS | 微调只做前向 | 只看 Forward FLOPS（原模型参数冻结） |
| 以为 AIPC 很强大 | 40 TOPS 其实很弱 | 1080 显卡都超过 40 TOPS，AIPC 噱头为主 |

### 5.2 量化方法选择避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| 以为 GGUF 是一种量化方法 | 网上以讹传讹 | GGUF 是**文件格式**，不是量化方法 |
| PTQ vs QAT 不知道怎么选 | 不知道场景 | 追求精度选 QAT，追求速度选 PTQ，**两者不互斥（可以先用 QAT 再用 PTQ）** |
| 觉得量化会大幅降低精度 | 理解有偏差 | INT4 损失约 0.03~0.07，QLoRA 几乎不影响最终效果 |
| 低估了双重量化的价值 | 不知道 scale 也占空间 | QLoRA 的第二个创新点就是对 scale 也做量化 |
| 以为对称量化就够了 | 没对比误差 | 非对称量化误差小 4-5 倍（0.03 → 0.007） |

### 5.3 硬件相关避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| 想买卡不知道怎么比较 | 只看显存不看算力 | 查维基百科显卡的 TFLOPS 数据 |
| 以为消费级显卡不能做微调 | 显存不够 | QLoRA（4bit）可以让 8B 模型跑在 12G 显卡上 |
| 搞不清各种精度 | FP16/BF16/TF32 太多 | 记一条：**微调用 BF16，推理用 INT4/INT8** |

### 5.4 老师经验总结

1. **"量化只有一个参数：load_in_4bit"** — 在 Unsloth 里就是 True/False 的事
2. **"NF4 比 INT4 好在中间密两边疏"** — 正态分布符合模型参数的实际情况
3. **"Q = Quantized，数字 = 目标 bit，字母 = 衣服尺码"** — GGUF 命名规则速记
4. **"PTQ 和 QAT 不打架，可以都要"** — 先用 QAT 边训练边量化，完了再用 PTQ 进一步压缩
5. **"GPU 天生适合做浮点运算，因为它本来是为游戏设计的"** — 弹道计算都是浮点数

## 6. 对比与思考

### 6.1 五种精度对比

| 精度 | 每参数 | 7B 模型大小 | 范围 | 精度 | 应用 |
|------|--------|------------|------|------|------|
| FP32 | 4 bytes | 28 GB | 最大 | 最高 | 训练基准 |
| FP16 | 2 bytes | 14 GB | 中等 | 高 | 训练/推理 |
| BF16 | 2 bytes | 14 GB | **跟 FP32 一样大** | 中（45% 尾数） | **微调推荐** |
| TF32 | 4 bytes | 28 GB | 跟 FP32 一样大 | 中（NVIDIA 专利） | 特定硬件加速 |
| INT8 | 1 byte | 7 GB | 有限 | 可接受 | 推理 |
| INT4 | 0.5 byte | 3.5 GB | 极小 | 轻微损失 | QLoRA |
| NF4 | 0.5 byte | 3.5 GB | 正态分布 | **优于 INT4** | QLoRA 默认 |

### 6.2 四种量化方法对比

| 方法 | 时机 | 精度 | 速度 | 实现复杂度 | 适用场景 |
|------|------|------|------|-----------|---------|
| **PTQ** | 训练后 | 较差（基准）| 快 | 简单 | 快速压缩已有模型 |
| **GPTQ** | 训练后 | 好 | 快 | 中等（分组并行） | PTQ 升级版 |
| **AWQ** | 训练后 | **很好** | 快 | 中等（1% 保护） | 极致压缩比 |
| **QAT** | 训练中 | **最好** | 慢 | 复杂（改模型） | 精度优先 |

### 6.3 对称 vs 非对称量化

| 维度 | 对称量化 | 非对称量化 |
|------|---------|-----------|
| 格子数 | 127（7bit） | 255（8bit） |
| 误差 | 0.056（约 1%） | 0.007（约 0.1%） |
| 计算复杂度 | 简单 | 稍微复杂 |
| 有没有零偏置 | 有（正方向浪费） | 无（全覆盖） |

### 6.4 量化的本质 trade-off

```
量化就是把每个参数的"分辨率"降低：
  
  FP32: 像用游标卡尺量距离（精确到 0.01mm）
  INT4: 像用卷尺量距离（精确到 1mm）
  
  游标卡尺 → 非常精确，但占地方（4 倍空间）
  卷尺 → 够用就好，但省地方（75% 空间节省）
  
  问题在于：你量桌子长度不需要游标卡尺的精度
  大模型也一样：大部分参数不需要 FP32 那么精确
```

## 7. 本节课思维导图

- 量化进阶
  - 上节课回顾
    - Soft Prompt = 让大模型帮你写提示词
    - 量化 = 让模型变小
  - 算力计算
    - TOPS（整数）vs TFLOPS（浮点）— 做微调看 TFLOPS
    - 三种场景计算
      - 训练耗时（epoch × batch × step_time）
      - 换卡提速（新旧算力比）
      - 换模型提速（FLOPS 比）
    - 工具：fvcore
    - 取值：Forward FLOPS（微调只用前向）
  - 浮点数存储
    - FP32 格式：S + E + M
    - 各种精度：FP16/BF16/TF32/INT8/INT4/NF4
    - BF16 = 范围大精度低（Google Brain）
  - 量化原理
    - 对称量化：零在中间，误差 ~0.03
    - 非对称量化：min~max 全覆盖，误差 ~0.007
    - 原理：取范围 → 算 scale → 映射 → 反量化
  - 训练时量化的难点
    - 权重在变 → 容易突破范围
    - 突破 → 重算 scale → 极其费时
    - 解决方案：PTQ（训练完再量化）
  - 四种量化方法
    - PTQ：训练后量化，简单兼容广
    - GPTQ：PTQ 优化，分组并行，精度更高
    - AWQ：保护 1% 重要权重，极致压缩
    - QAT：训练中量化，精度最高
    - QLoRA = QAT + NF4 + 双重量化
  - GGUF 文件格式
    - 不是量化方法，是文件格式
    - 命名规则：Q{bit}_{尺码}
    - Q4_K_M = 4bit 分组量化中号
  - 代码演示
    - TorchTune 做 QAT（全量微调 + QAT）
    - TorchTune 做 PTQ（训练后量化）
    - 配置：Int8DynamicActivationInt4WeightQuantizer
  - 课后
    - 下节：多模态（CNN）
    - 面试重点：量化原理、PTQ vs QAT、QLoRA 创新点
