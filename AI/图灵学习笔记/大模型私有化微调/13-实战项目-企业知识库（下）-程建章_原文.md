### 2.3 向量数据库与模型配置

剩下的配置中，向量数据库的 host 填写 `127.0.0.1`（服务都运行在同一台服务器上），user 和 password 不需要，注释掉即可。

**Embedding 模型**要和 Index 项目中的 embedding 模型保持一致。因为在建索引时做的向量化和检索时的向量化，必须用同一个模型才能做对比、计算向量之间的关系。

这次还配置了一个 **Rerank 模型**。作用是从向量数据库检索出一组比较接近的文档后，再做一层精排——这之前老师应该讲过了。

三个模型的 Key 都是一样的（都是百炼平台）。

### 2.5 回调接口说明

企业微信的回调流程：
- 配置时会验证回调接口的有效性
- 根据签名、时间戳、nonce 等参数验证解密是否正确
- 将一段 string 加密后，要求解密出 echo string 返回
- 解密成功才认为回调接口符合要求，配置成功

项目中有两个核心方法：

**`callback` 方法（GET）** — 接收企业微信的校验请求，验证回调接口是否正常。

**`callback` 方法（POST）** — 接收企业微信发来的消息通知。消息通过加密工具对象解密后获取 message 内容。

微信客服可以接收文本、图片、文件、表情、语音等多种格式。当前程序主要针对**文本消息**做了处理，使用 `handle_message` 方法处理所有通知消息。对于图片、声音、视频等，仅做简单回复。

### 2.6 智能回复系统

文本消息的核心处理逻辑是 **`smart_reply`**（智能回复）。

```python
# 核心流程
rag_service.get_reply(user_query)
```

RAG Service 中有一个**提示词模板**，将知识库内容和用户问题组装进去。回答要求：
- 知识库有明确答案的 → 准确回答
- 信息不完整 → 提示联系人工客服
- 完全没有相关信息 → 礼貌说明不知道

**查询流程**：
1. 第一步是场景检测（可选，当前未启用）— 探测用户是在投诉、查询订单还是咨询
2. 从向量数据库获取候选文档
3. 使用 LangChain 对 Milvus 的封装进行检索

### 2.7 向量检索参数

关键技术参数：

| 参数 | 值 | 说明 |
|------|-----|------|
| 索引类型 | IVF_FLAT | 建索引时选用的类型 |
| 度量方法 | COSINE | 余弦相似度 |
| nlist | 1024 | 将向量分成多少个区块 |
| nprobe | 64 | 搜索时在多少个最相关分组中比对 |

nlist 和 nprobe 的关系：nlist=1024 把向量库分成 1024 个聚类，搜索时 nprobe=64 只在这 64 个最相关的分组中仔细比对。建议比例是 nprobe ≈ nlist / 16。

## 4. Minor u GPU PDF 解析部署

### 4.1 启用 Minor u 配置

Index 项目中之前安装时把 Minor u 的安装包注掉了，现在打开配置：

1. 切换到 online 环境
2. 安装依赖（大约 3-5 分钟）
3. 修改 `.env`，配置 Minor u 服务器地址

### 4.2 AutoDL 算力服务器创建

去 AutoDL 平台租用 GPU 服务器：

1. **选算力** — 选择 4090，框架 PyTorch 2.5.1，Python 3.12，CUDA 12.4
2. **找机器** — 在北京 B 区找 4090，留意每个机器的 CUDA 驱动版本
3. **选镜像** — 基础镜像选 PyTorch 2.5.1
4. **开机** — 每小时约 2 块钱

注意：一个机器上有 8 个实例，如果只剩 1 个，停了以后过两天再启动，如果机架上没有空闲卡了就没办法启动。

开机后能看到 SSH 命令、密码等信息。

### 4.3 SSH 密钥配置（推荐）

配置密钥登录可以提升效率：

```bash
# 在服务器上生成密钥
ssh-keygen -t rsa
# 公钥在 ~/.ssh/id_rsa.pub，可随意上传
# 私钥在 ~/.ssh/id_rsa，切勿泄露
```

在 AutoDL 的控制台 → 设置密钥登录，配置好后所有启动的实例都能自动登录。

SSH Config 配置示例（Windows 也适用）：

```
Host autodl
    HostName <服务器IP>
    User root
    Port <端口号>
    IdentityFile ~/.ssh/id_rsa
```

### 4.4 安装 Minor u

```bash
# SSH 登录到 AutoDL 服务器
ssh root@<服务器IP> -p <端口>

# 设置缓存目录到数据盘（系统盘只有 30G 不够用）
export UV_CACHE_DIR=/autodl-temp/.cache

# 安装 Minor u 2.0.6
uv pip install minor-u==2.0.6

# 设置模型源
export MINOR_U_MODEL_SOURCE=modelscope

# 启动服务（后台运行）
nohup minor-u-server > minor_u.log 2>&1 &
```

启动成功后看到 `Server is fired up and ready` 的提示。

Minor u 是基于大模型 GPU 算法的 PDF 解析工具。相比普通的 PDF 解析器（如 PyPDF2、pymupdf），它能处理包含图片、复杂格式的 PDF，将其解析为结构化的 Markdown 文本。

### 4.5 SSH 端口转发

因为 AutoDL 的显卡服务器没有公网端口，需要通过 SSH 端口转发来访问：

```bash
# 本地转发：将外部服务器的 30000 端口转发到 Minor u 服务器的 30000 端口
ssh -N -L 30000:localhost:30000 root@<AutoDL服务器IP> -p <端口>

# 使用密钥登录的简化版
ssh -N -L 30000:localhost:30000 autodl
```

SSH 端口转发的优势：只要有 SSH 能到达的地方，就能无障碍地访问所有服务。

测试连接：

```bash
# 在项目目录下运行测试
cd test
python test_minor_u.py
```

测试脚本会读取一个 PDF 文件，通过 Minor u 的 API 进行解析，输出 Markdown 格式的结果。和普通的 PDF 解析相比，Minor u 增加了大量格式性的内容。

成本对比：
- PyMuPDF：CPU 即可运行，免费
- Minor u：需要 GPU（AutoDL 约 3 元/小时），解析质量更高

## 5. 索引类型技术说明

### 5.1 当前配置

项目当前使用 **IVF_FLAT** 索引类型 + **余弦相似度**作为度量方法。

参数：
- **nlist = 1024**：将向量空间划分成 1024 个区块（聚类中心）
- **nprobe = 64**：搜索时只在最相关的 64 个分区中比对

### 5.2 常见索引类型对比

| 索引类型 | 原理 | 优点 | 适用场景 |
|---------|------|------|---------|
| **FLAT** | 暴力搜索，逐一比较 | 召回率最高，不漏检 | 数据量小，追求准确率 |
| **IVF_FLAT** | 预聚类划分区块，只搜命中区块 | 检索效率高 | 当前项目使用 |
| **IVF_SQ8** | 在 IVF 基础上将 float 量化为 8bit 整数 | 压缩率高，省内存 | 内存受限的场景 |
| **IVF_PQ** | 子空间编码进一步压缩 | 极高压缩率 | 大规模数据集 |
| **HNSW** | 分层图索引，由粗到精逐层细化 | 搜索速度极快 | 低延迟要求，大规模数据 |

### 5.3 决策矩阵

| 条件 | 推荐索引 |
|------|---------|
| 数据量小 | FLAT 或 IVF_FLAT |
| 低延迟要求 | IVF_FLAT |
| 内存受限 | IVF_SQ8（量化压缩） |
| 数据量非常大 | HNSW 或 IVF_PQ |
| 追求简单准确 | 全表扫描（FLAT） |

> **注意**：建索引和搜索时，度量方法必须保持一致。

## 6. Mini IO 分布式部署

### 6.1 为什么需要分布式存储

当前存储直接运行在 Docker 中，演示可以，但生产环境有风险——万一 Docker 或存储卷发生问题，数据就没了。程序可以重新部署，但数据搞起来很麻烦。分布式存储解决可用性和安全性问题。

### 6.2 创建服务器实例

在阿里云创建两台 ECS 实例（做分布式 Mini IO 集群）：

1. **可用区**：必须与外部服务（Index / Docker）在同一个 VPC 内，保证互通
2. **规格**：选最低配即可，约 47 元/月（用完建议销毁）
3. **镜像**：选择系统盘大小合适即可
4. **数据盘**：加 4 块盘（2×4 配置）
5. **公网 IP**：存储和数据库一般不分配公网 IP，没有 IP 才最安全
6. **安全组**：新建安全组，开通内网全部端口
7. **密钥对**：和之前使用同一个，方便管理

### 6.3 数据盘格式化

```bash
# 查看所有磁盘
lsblk

# 格式化为 XFS 格式
mkfs.xfs /dev/vdb
mkfs.xfs /dev/vdc
mkfs.xfs /dev/vdd
mkfs.xfs /dev/vde

# 创建挂载目录
mkdir -p /data/disk{1,2,3,4}

# 挂载
mount /dev/vdb /data/disk1
mount /dev/vdc /data/disk2
mount /dev/vdd /data/disk3
mount /dev/vde /data/disk4

# 确认挂载
df -h
```

### 6.4 安装与配置 Mini IO

```bash
# 下载 Mini IO 二进制（需提前下载，因为两台机器没有公网）
# 通过 SCP 复制到两台机器
scp minio root@<IP1>:/usr/local/bin/
scp minio root@<IP2>:/usr/local/bin/

# 安装
dnf install minio -y

# 创建运行用户
useradd -r minio-user
chown minio-user:minio-user /usr/local/bin/minio

# 验证
minio-user list  # 能列出说明有查看权限
```

配置 hosts 域名：

```
# /etc/hosts
172.x.x.4  minio1
172.x.x.5  minio2
```

创建配置文件：

```bash
# /etc/minio/config.env
MINIO_VOLUMES="http://minio{1...2}/data/disk{1...4}"
MINIO_OPTS="--address :9001"
MINIO_ROOT_USER=admin
MINIO_ROOT_PASSWORD=admin123
```

### 6.5 启动与验证

```bash
# 在两台机器上分别启动
minio server /etc/minio/config.env

# 查看日志
journalctl -u minio -f
```

验证集群状态：
- 访问任一节点的 9001 端口
- 查看 Monitor → 矩阵，确认两台 Server 状态为 Online
- 可用磁盘共 8 块（2 台 × 4 盘）

创建 Bucket 后，就可以像之前一样使用。

### 6.6 切换到分布式存储

将项目中的环境变量从本地 Mini O 改为分布式 Mini O：

```env
# 之前（本地）
S3_ENDPOINT=http://localhost:9001
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin

# 之后（分布式）
S3_ENDPOINT=http://minio1:9001  # 或 minio2，两者对等
MINIO_ACCESS_KEY=admin
MINIO_SECRET_KEY=admin123
```

两个节点是对等的，选任何一个都可以。生产环境一般会在前面加一个负载均衡。

Access Key 在 Milvus 的环境变量中配置（`MINIO_ACCESS_KEY` 和 `MINIO_SECRET_KEY`）。

## 7. 扩展话题：腾讯开源 RAG 平台

### 7.1 对话开放平台

腾讯最近开源了一个 RAG 项目，在微信官网上可以看到其重量级——**对话开放平台**，使用了开源的模块化 RAG 企业问答服务。

虽然很多人觉得 RAG 好像越来越普通了，不如 Agent 性感，但 RAG 就像传统开发中的"增删改查"——不性感但很重要。我们工作中百分之六七十的服务都在做类似的事情。包括腾讯这样的公司，也依然在 RAG 领域继续深耕。

### 7.2 主要特性

- **零代码部署**，覆盖腾讯生态
- **支持 MCP 服务**
- 基于 Web UI 的配置
- 主要服务用 **Go 语言** 编写
- 技术栈：PostgreSQL（主数据库 + 向量存储）、Redis（流处理管理）、Mini O（对象存储）
- 支持本地 Ollama 推理

### 7.3 IMA 架构流程

```
get source → chunk → embedding → index storage
query → query translation → query processing → retrieve → rerank → LLM → response generation
```

这个流程和我们的项目基本一致。虽然不新颖，但把它用好、做工程化落地，是很不容易的事情。
