# 量化 (Quantization) Part 2 — 算力与高级量化方法

## 回顾：量化的目标与原理

- **量化的目标**：让模型变小 → 模型变小以后计算量下降 → 推理/训练变快
- **量化的原理**：把连续值变成离散值（连续 → 离散）
- 原始权重经过量化后变小，成为新权重；原始权重被删除，模型体积减小
- 模型变小后，显存需求也降低
- 量化后的值在推理时会**反量化还原**成近似值

---

## 一、算力衡量：TOPS vs TFLOPS

### 基本概念

| 指标 | 全称 | 含义 | 推崇方 |
|------|------|------|--------|
| **TOPS** | Trillions Operations Per Second | 整数运算能力（每秒万亿次整数四则运算） | CPU厂商（Intel、微软） |
| **TFLOPS** | Trillion Floating-point OPS | 浮点运算能力（每秒万亿次浮点运算） | GPU厂商（NVIDIA、寒武纪等NPU厂商） |

### AIPC 标准

- Intel 与微软联合提出 **AIPC（AI PC）** 概念
- 要求 NPU 或 GPU 的算力 ≥ **40 TOPS**，才可张贴 AIPC 标识
- 40 TOPS 其实很弱：GTX 1080 等老旧显卡都已超过该标准，RTX 3090 更是远超

### 为什么 CPU 厂商推崇 TOPS 而非 TFLOPS？

- **CPU 不擅长浮点运算**，而 GPU 天然擅长（出身于游戏图形计算：角度、弹道、多边形等全是浮点数）
- 大模型权重都是浮点数（0.xxx、1.xxx），因此 **TFLOPS 对 AI/LLM 工作更重要**
- CPU 厂商推 TOPS 的逻辑：通过**量化**将模型转为整数运算，让 CPU/NPU 的 TOPS 算力能派上用场

### 结论

- 做微调或大模型推理时，应**偏重 TFLOPS**
- 若要在终端设备（用户本地 PC）运行模型，需要**量化**成整数运算，才能利用 AIPC 的 TOPS

## 二、训练时间 / 算力计算（三种场景）

### 场景一：估算训练时间

公式：**总训练时间 = steps × 每步耗时**

```
steps = (data_size / batch_size) × epochs
```

**示例**：
- 数据集 5 万张图像，batch_size = 100，训练 20 轮
- GPU 每处理 100 张图像需要 0.2 秒
- 每轮 batch 数 = 50000 / 100 = 500
- 每轮耗时 = 500 × 0.2 = 100 秒 ≈ 1.67 分钟
- 总时间 = 1.67 × 20 = **33.4 分钟**

### 场景二：新旧 GPU 对比

公式：**新卡耗时 = 旧卡耗时 × (旧卡 TOPS / 新卡 TOPS)**

- 算力翻倍，耗时减半
- 显卡算力可查维基百科（不同精度下的 TFLOPS / TOPS）

### 场景三：不同模型对比

使用 **flop-counter** 库（`pip install fvcore`）计算模型浮点运算量：

```python
from fvcore.nn import FlopCountAnalysis

# 计算模型 forward 的 FLOPS
flops = FlopCountAnalysis(model, input_tensor)
```

- 输出四个值：
  1. **forward MACs**（前向矩阵乘积累加次数）
  2. **forward FLOPS**（前向浮点运算次数）
  3. **forward + backward MACs**
  4. **forward + backward FLOPS**
- **计算模型对比时应使用 forward FLOPS**（微调时只调新加的参数，不反向传播修改基座模型，故只需前向推理算力）

**示例**：
- LLaMA 7B：forward FLOPS = 1700G
- 千问 1.7B：forward FLOPS = 360G
- 已知训练千问 1.7B 需 1 小时 → 训练 LLaMA 7B 约需 1700/360 ≈ 4.7 小时

## 三、浮点数存储（IEEE 754）

### 基本结构

浮点数由三部分组成：

| 精度 | 符号位 (S) | 指数位 (Exponent) | 尾数位 (Fraction/Mantissa) | 总位数 |
|------|-----------|-------------------|---------------------------|--------|
| **FP32** (float) | 1 | 8 | 23 | 32 |
| **FP16** | 1 | 5 | 10 | 16 |
| **BF16** (Brain Float, Google) | 1 | 8 | 7 | 16 |
| **TF32** (NVIDIA TensorFloat) | 1 | 8 | 10 | 19 (32位封装) |
| **FP64** (double) | 1 | 11 | 52 | 64 |

### 计算公式

```
value = (-1)^S × 2^(E - bias) × (1 + Fraction)
```

- FP32 的 bias = 127
- 示例：二进制 `0 01111100 01100000000000000000000`
  - S=0, E=124, Fraction = 2^(-2) + 2^(-3) = 0.25 + 0.125 = 0.375
  - value = 1 × 2^(124-127) × (1.375) = 2^(-3) × 1.375 = **0.171875**

### 关键理解

- 浮点数不能精确存储所有小数（只能是 2 的幂次组合，即 0.5, 0.25, 0.125...）
- 小数存进浮点数再取出，一定不是原来的值 → **浮点数天然有误差**
- 编程中存金额等精确数字时，不应使用浮点数

### BF16 与 FP16 的对比

- BF16 移动了 3 位从尾数到指数（FP16: 1+5+10 → BF16: 1+8+7）
- 效果：**范围变大**（Exponent 更大），**精度变低**（Fraction 更小）
- BF16 的 B 来自 Google Brain 团队
- TF32 的 T 来自 Tensor（张量）

### 为什么 NVIDIA / Google 要发明新精度？

- 大模型训练中，**范围比精度更重要**
- 将部分精度比特挪给指数位，扩大可表示的范围

## 四、量化详解

### 核心思想

将连续浮点数映射到离散的整数值（如 INT4 / INT8），减少每个值的存储空间。

- 比特数越少 → 格子（分段）越稀疏 → 精度越低 → 存储越小
- 比特数越多 → 格子越密 → 精度越高 → 存储越大

### 对称量化（Symmetric Quantization）

- 以 0 为中心，取正负两侧的最大绝对值作为范围
- 格子覆盖 [-max, +max]

**示例**：将 Float 矩阵量化到 INT8
- 矩阵范围：[-7.59, 18.0]
- 取最大绝对值：10.8（实际以正最大值 18 为半幅会浪费一部分）
- Scale = 18.0 / 127 ≈ 0.085
- 量化 5.47：5.47 / 0.085 ≈ 64（取整）
- 反量化：64 × 0.085 = **5.44**（原值 5.47，误差 0.03）

### 非对称量化（Asymmetric Quantization）

- 不锁定在 0 点，使用 min 到 max 的全范围
- 需要计算 zero-point（偏移量）

**示例**：
- 矩阵范围：[-7.59, 18.0]
- 全长 = 18.0 - (-7.59) = 27.59
- Scale = 27.59 / 255 ≈ 0.072（格子更细，精度更高）
- 量化 5.47：value = (5.47 - (-7.59)) / 0.072 ≈ 181
- 反量化：181 × 0.072 + (-7.59) = **5.463**（原值 5.47，误差 0.007）

### 对称 vs 非对称对比

| | 对称量化 | 非对称量化 |
|--|---------|-----------|
| 计算 | 简单（zero-point=0） | 较复杂（需计算偏移量） |
| 精度 | 较低（部分范围浪费） | 较高（充分利用全部量化范围） |
| 格子粒度 | 较粗 | 较细 |
| 误差 | 较大（例：0.03） | 较小（例：0.007） |

### 量化的难点

- 训练过程中权重值不断变化，可能突破已确定的量化上下限
- 若突破上限，整个网络的量化需重新计算 → 代价极大

## 五、四种量化方法

### 1. PTQ（Post-Training Quantization）

**训练后量化**

- **做法**：等待完整训练/微调完成后，对最终权重矩阵做量化
- **优点**：
  - 不需要修改原始训练过程
  - 兼容各种模型（训练与量化完全脱钩）
  - 使用简单
- **缺点**：精度不如训练中量化的方法高

### 2. QAT（Quantization-Aware Training）

**训练中量化**（边训练边量化）

- **做法**：在训练过程中加入量化层，将量化/反量化的误差计入 loss 计算
- **优点**：
  - 精度更高（反向传播可以影响量化层，从 loss 中选择更优的量化结果）
- **缺点**：
  - 训练变慢（多出量化层，前向 + 反向都需包含量化操作）
  - 网络结构改变（增加线性量化层）
  - 超参调优更复杂
- **实践中**：在 unsloth 框架中，`load_in_4bit=True` 就开启了 QAT

### PTQ vs QAT 对比

| | PTQ | QAT |
|--|-----|-----|
| 时机 | 训练完成后 | 训练过程中 |
| 模型修改 | 无需修改 | 需增加量化层 |
| 训练速度 | 不受影响 | 变慢 |
| 精度 | 较低 | 更高 |
| 复杂度 | 简单 | 复杂 |

> 两者不矛盾，可以组合使用：训练中用 QAT 量化，训练完再用 PTQ 进一步量化。

### 3. GPTQ（GPT Post-Training Quantization）

PTQ 的改进优化方向之一。

- **核心创新**：基于**二阶信息（Hessian 矩阵）** 做量化
- **综合了 4 篇前人论文的方法**（OBD、OBS、OBC、OBQ）
- **分组并行量化**：
  - 将权重矩阵按行/列分组，每组独立量化
  - 每组有自己的 scale 值
  - 可并行计算（多核/多 GPU）
- **优点**：精度更高、速度更快
- **代价**：需存储多个 scale 值（空间换并行），反量化时查表更复杂
- **应用**：广泛使用的成熟算法，适合对 GPT 系列（Decoder-only）模型做量化

### 4. AWQ（Activation-Aware Weight Quantization）

- **核心发现**：不是所有权重同等重要
- **做法**：
  - 找出最重要的 ~1% 权重（根据激活值大小判断）
  - 重要权重用更高精度（如 FP16），其余用更低精度（如 INT3 / INT4）
  - 实现**可变比特量化**（不同矩阵/权重用不同精度）
- **效果**：保护 1% 的关键权重即可大幅减少量化误差
- **相关实现**：1.58-bit 量化等极端低比特方案
- **与 LoRA 的相似思路**：类似 Adaptive Rank — 重要的保留高精度，不重要的降低精度

## 六、GGUF 文件格式

### GGUF 不是量化方法（常见误区）

- GGUF 是一种**文件格式**，不是量化方法
- unsloth 最终导出的模型文件即为 `.gguf` 格式

### GGUF 命名规则

```
<base_name>-<size_label>-<fine_tune_info>-<encoding>.gguf
```

示例：`Llama-2-13B-chat-Q4_K_M.gguf`

**encoding 字段说明**：

| 字段 | 含义 |
|------|------|
| **Q** | Quantized（已量化） |
| **数字** | 量化目标比特数（如 Q4 = 4-bit） |
| **K** | 量化方案（K-quant scheme） |
| **X S / S / M / L / XL** | 模型大小编码（类似衣服尺码） |

- Q4_K_M 表示 4-bit 量化、K 方案、中等大小
- Q3_K_S 表示 3-bit 量化、K 方案、小尺寸
- 同比特数下还有细分（如 Q4 中偏大和偏小版本）

## 七、Q-LoRA（Unsloth 实现）

### 核心创新点一：NF4 代替 INT4

- **NF4 = Normal Float 4-bit**
  - INT4：0~255 均匀分布（均匀量化）
  - NF4：基于**正态分布**（中间密、两边疏），更符合权重实际分布
  - 中间权重密集的区域格子更细 → 精度更高
  - 边权重稀疏的区域格子更粗 → 不浪费量化资源

### 核心创新点二：Scale 量化

- 分组量化会产生大量小数 scale 值
- Q-LoRA 对这些 scale 值也做进一步量化 → 进一步压缩存储

### 实践中使用

```python
# unsloth 中开启 QAT + Q-LoRA
model = FastLanguageModel.from_pretrained(
    model_name,
    load_in_4bit=True,  # 等价于 load_in_4bit = True
    # ...
)
```

- `load_in_4bit=True` 即开启 Q-LoRA
- qLoRA 相比原始 LoRA 只有约 1/4 的大小
- `load_in_4bit=False` → LoRA 精度更高，但显存更大
- 选择依据：你能容忍多慢的速度？想快 → True；想精度高 → False

## 总结

```
量化目标：模型变小 → 推理/训练变快
  └─ 原理：连续值 → 离散值（连续浮点数映射到有限整数格点）
        ├─ 对称量化：以零为中心，简单但精度略低
        └─ 非对称量化：min-max 全范围，精度高但计算复杂

算力衡量：
  ├─ TOPS（整数）← CPU 厂商推，AIPC 标准 ≥ 40 TOPS
  └─ TFLOPS（浮点）← GPU 擅长，对 AI 更重要

训练时间估算：
  总时间 = steps × 每步耗时 = (data_size/batch_size) × epochs × 每步耗时
  新旧卡对比：新耗时 = 旧耗时 × (旧TOPS / 新TOPS)
  换模型对比：使用 flop-counter 算 forward FLOPS

四种量化方法：
  ├─ PTQ：训练后量化（简单、通用、精度较低）
  ├─ QAT：训练中量化（精度高、训练慢、需改网络）
  ├─ GPTQ：PTQ 改进版（二阶信息 + 分组并行）
  └─ AWQ：保护重要 1% 权重用高精度，其余低比特

GGUF：文件格式（不是量化方法）

Q-LoRA：NF4（正态分布量化）+ Scale 量化
```
