# PEFT（参数高效微调）是什么

## 1. 课程元信息

- **主题**：PEFT（Parameter-Efficient Fine-Tuning）的概念、分类与应用场景
- **面试重点**：广度拓展（多列举几种 PEFT 方式），而非深度钻某一种
- **前置知识**：大模型基础概念、全参数微调、Transformer 注意力机制

---

## 2. 核心概念图谱

| 术语 | 英文 | 通俗解释 |
|------|------|---------|
| 参数高效微调 | PEFT (Parameter-Efficient Fine-Tuning) | 冻结大部分参数，只训练少量额外参数来适配下游任务 |
| 全参数微调 | Full Fine-Tuning | 更新模型所有参数，资源消耗大，易灾难性遗忘 |
| 灾难性遗忘 | Catastrophic Forgetting | 微调后模型丢失了预训练的通用知识 |
| Adapter 适配器 | Adapter Tuning | 在模型层间插入小型网络进行微调 |
| LoRA | Low-Rank Adaptation | 对权重矩阵做低秩分解，只训练低秩矩阵 |
| Prefix Tuning | Prefix Tuning | 在注意力计算的 Q/K 前添加可学习的 prefix 向量 |
| 重参数化 | Re-parameterization | 将训练参数重新参数化为另一种形式（如 LoRA） |
| 剪枝 | Pruning | 移除对任务不重要的参数连接 |
| 蒸馏 | Distillation | 用大模型（教师）指导小模型（学生）学习 |

---

## 3. 技术原理 / 流程拆解

### 3.1 全参数微调 vs PEFT

```
全参数微调：
  [预训练模型] → 更新 100% 参数 → [下游任务模型]
  7B 模型需要 ~28GB 显存（参数量 × 4 字节）
  175B 模型需要 ~700GB 显存
  缺点：资源需求大、灾难性遗忘、难以回滚

PEFT：
  [预训练模型（冻结）] + [少量可训练参数] → [下游任务模型]
  可训练参数只有原始模型的 0.1% ~ 1%
  显存需求大幅降低
  优点：资源消耗低、不遗忘预训练知识、可热插拔
```

**显存估算公式**：模型参数量 × 4 字节 ≈ 所需显存

### 3.2 三种主流 PEFT 方法

#### 方法一：Adapter Tuning（适配器方法）

```
原始 Transformer 层：
  [Attention] → [FFN] → [输出]

插入 Adapter 后：
  [Attention] → [FFN] → [Adapter] → [输出]
                          ↓
                  Linear(大R → 小r)     ← 降维
                  ReLU
                  Linear(小r → 大R)     ← 升维
```

- 核心：先降维再升维的"瓶颈"结构
- 小 r 远小于大 R（可缩小几十到几百倍）

#### 方法二：Prefix Tuning（提示工程方法）

```
原始注意力公式：
  Attention(Q, K, V) = softmax(Q × K^T / √d_k) × V
  
Prefix Tuning 后：
  Q × [Prefix_K; K]^T     ← 在 K 前面拼接可学习的 prefix 向量
  [Prefix_V; V]           ← 在 V 前面拼接可学习的 prefix 向量
```

- 不修改模型参数，只学习少量的 prefix 嵌入
- 每个任务维护自己的 prefix，可热插拔

#### 方法三：LoRA（重参数化方法，也是最常用的）

（后面第19节会专门展开，这里只做概述）

```
原始权重矩阵: W (d×d)
LoRA 分解:   W + ΔW = W + B×A
             B: d×r, A: r×d, r << d
训练时: W 冻结，只训练 B 和 A
推理时: B×A 合并回 W，无额外推理开销
```

### 3.3 PEFT 核心优势

| 优势 | 说明 |
|------|------|
| 资源消耗降低 | 可训练参数减少 90%~99%，显存需求大幅下降 |
| 效率提升 | 训练速度更快，数据需求更少 |
| 模型兼容性强 | 只要模型有矩阵运算就能做 PEFT |
| 无灾难性遗忘 | 基座模型参数冻结，不丢失预训练知识 |
| 可热插拔 | 同时保留多个任务的微调参数，切换任务时只需换 Adapter/LoRA 权重 |

---

## 4. 避坑指南

| 注意点 | 说明 |
|--------|------|
| 显存估算"乘4"是粗略值 | 实际还受优化器状态、batch size 等因素影响 |
| Adapter 会增加推理延迟 | 额外层会在推理时增加计算量（LoRA 无此问题） |
| Prefix Tuning 的效果与任务相关 | 某些任务上效果不如 Adapter 或 LoRA |
| 剪枝方法通用性差 | 好的剪枝方法不多，很多是通用性差或投入产出比低 |

---

## 5. 对比与思考

### 5.1 三种 PEFT 方法对比

| 方法 | 核心思想 | 是否改模型结构 | 推理额外开销 | 典型应用 |
|------|---------|--------------|------------|---------|
| Adapter Tuning | 插入小网络 | 是（层间插入） | 有 | NLP 各任务 |
| Prefix Tuning | 添加 prefix 向量 | 否 | 无 | 文本生成 |
| **LoRA** | 低秩矩阵分解 | 否 | **无**（可合并） | **最常用** |

### 5.2 PEFT 的未来方向

- **小模型 + 低门槛微调**：千问 0.7B 等小模型效果已不错，结合 PEFT 可实现个人化定制
- **训练与使用同步**：模型在使用过程中持续微调（如 LoRI，比 LoRA 更省资源）
- **大模型落地方向**：从"大而全"转向"小而精"，PEFT 是关键使能技术
