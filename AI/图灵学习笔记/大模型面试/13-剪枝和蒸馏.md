# 剪枝（Pruning）和蒸馏（Distillation）

## 1. 课程元信息

- **主题**：模型压缩的两种主流方式 — 剪枝 vs 蒸馏
- **前置知识**：深度学习基础、模型训练流程
- **核心目标**：理解剪枝和蒸馏的核心原理、优缺点及适用场景

---

## 2. 核心概念图谱

| 术语 | 英文 | 通俗解释 |
|------|------|---------|
| 剪枝 | Pruning | 删除模型中不重要的参数/连接，减少模型大小 |
| 结构化剪枝 | Structured Pruning | 删除整层或整个通道，对硬件友好 |
| 非结构化剪枝 | Unstructured Pruning | 随机删除单个参数，需专用硬件 |
| 知识蒸馏 | Knowledge Distillation | 大模型（教师）教小模型（学生）学习 |
| 教师模型 | Teacher Model | 效果好的大模型，作为知识来源 |
| 学生模型 | Student Model | 待训练的小模型，模仿教师输出 |
| 蒸馏坍塌 | Distillation Collapse | 学生模型过小，无法学到教师的泛化能力 |
| KL 散度 | KL Divergence | 衡量两个概率分布差异的损失函数 |

---

## 3. 技术原理 / 流程拆解

### 3.1 模型压缩四种方式（按压缩度从低到高）

```
1. 剪枝（Pruning）    → 删除不重要参数，压缩几倍
2. 蒸馏（Distillation） → 大模型教小模型，压缩几十倍
3. 量化（Quantization） → 降低参数精度（FP16 → INT8），后面细讲
4. 二值化（Binarization）→ 参数只有 +1/-1，压缩度最高
```

### 3.2 剪枝（Pruning）

**核心思想：** 删除对模型输出影响最小的参数/连接/通道

```
原始模型 → 评估参数重要性 → 删除不重要参数 → 微调恢复精度
                  ↓
      可控制删除比例（10% ~ 90%）
```

**两种剪枝方式：**
| 方式 | 做法 | 优缺点 |
|------|------|--------|
| 结构化剪枝 | 删除整层/整个通道 | ✅ 硬件友好，推理加速明显 <br> ❌ 精度损失可能较大 |
| 非结构化剪枝 | 随机删除单个参数 | ✅ 压缩率灵活 <br> ❌ 需要专用硬件（稀疏算子），通用设备加速效果差 |

**剪枝的优缺点：**
| 优点 | 缺点 |
|------|------|
| 精度损失可控（可自选删除比例） | 自动化难度高（需人工评估重要性） |
| 硬件友好（结构化剪枝） | 不同模型适配性差异大 |
| 直接提升推理速度 | 非结构化需专用硬件 |
| 计算成本显著降低 | 剪枝后可能需要 fine-tuning 恢复精度 |

**实际案例 — 智能驾驶：**
- 车机端：剪枝后的模型处理**常规场景**（红绿灯、斑马线、双黄线）
- 云端：完整大模型处理**非常规场景**（识别失败的复杂场景）
- 车机判断"yes"→ 本地识别，"no"→ 上传云端

### 3.3 知识蒸馏（Distillation）

**核心思想：** 大模型（教师）的输出作为小模型（学生）的训练目标

```
训练阶段：
  [教师模型（大）] ─── 输出概率分布（软标签）───┐
                                               ├──→ [损失函数] → 更新学生
  [训练数据] → [学生模型（小）] ─── 输出概率 ──┘

损失函数 = α × KL散度(教师输出, 学生输出) + (1-α) × 交叉熵(学生输出, 硬标签)
```

**蒸馏的优点：**
| 优点 | 说明 |
|------|------|
| 精度保持能力强 | 学生可学到教师的"软知识"（概率分布） |
| 甚至可能超越教师 | 学生不问"无用问题"，不走弯路 |
| 通用性高 | 适用于各种模型架构 |
| 训练流程标准化 | 设置好 KL 散度 + 交叉熵即可 |

**蒸馏的缺点：**
| 缺点 | 说明 |
|------|------|
| 依赖强教师 | 教师模型本身效果不好，学生上限受限 |
| 训练成本高 | 需同时运行教师和学生模型，显存和计算量翻倍 |
| 蒸馏坍塌 | 学生模型过小 → 无法拟合教师的泛化能力 |
| 非开源模型不便 | 如 GPT-4 未开源，调用成本高 |

**蒸馏坍塌的表现：**
```
大模型（500B）→ 教 → 小模型（1B）
  ↓
小模型记住了"核心知识"（类似背书）
但学不会"泛化能力"（类似写诗）
  ↓
对所有词的概率输出模糊 → [0.2, 0.3, 0.2, 0.1, 0.2]
分不清重点和非重点 → 蒸馏坍塌
```

## 4. 剪枝 vs 蒸馏对比

| 对比维度 | 剪枝 | 蒸馏 |
|---------|------|------|
| 原理 | 删除不重要参数 | 大模型教小模型 |
| 压缩率 | 几倍（10%~90% 参数） | 几十倍（参数量大幅缩减） |
| 精度保持 | 可控，需微调恢复 | 好，甚至可能超教师 |
| 训练成本 | 低（剪枝后微调即可） | 高（需同时运行两个模型） |
| 硬件需求 | 结构化剪枝友好 | 训练时需要大显存 |
| 通用性 | 不同模型差异大 | 通用性高 |
| 适用场景 | 精度要求高的场景（自动驾驶） | 需要快速部署小模型的场景 |

---

## 5. 本节课思维导图

- 模型压缩方式
  - 剪枝（Pruning）
    - 结构化（删整层，硬件友好）
    - 非结构化（删单个参数，需专用硬件）
    - 优点：精度可控、成本低、推理加速
    - 缺点：自动化难、适配性差异大
    - 案例：车机+云端协同
  - 蒸馏（Distillation）
    - 教师模型 → 学生模型
    - 损失：KL散度 + 交叉熵
    - 优点：精度保持、通用性高
    - 缺点：成本高、依赖强教师、蒸馏坍塌
    - 蒸馏坍塌：模型过小→泛化能力丢失→概率模糊
  - 量化（后续细讲）
  - 二值化（后续细讲）
