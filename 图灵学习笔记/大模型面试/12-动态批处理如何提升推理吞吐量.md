# 动态批处理如何提升推理吞吐量

## 1. 课程元信息

- **主题**：动态批处理（Dynamic Batching）的原理、实现与效果
- **前置知识**：GPU 并行计算、Transformer 推理中的 Padding 机制、KV Cache
- **核心目标**：理解静态批处理的缺陷，以及动态批处理如何通过分组和弹性触发条件大幅提升吞吐量

---

## 2. 核心概念图谱

| 术语 | 英文 | 通俗解释 |
|------|------|---------|
| 静态批处理 | Static Batching | 固定 batch size，人不满不让进，GPU 有空闲浪费 |
| 动态批处理 | Dynamic Batching | 按请求长度分组 + 弹性触发条件，动态决定 batch |
| 填充 | Padding | 将批次内不等长的序列补齐到统一长度 |
| 序列长度分组 | Length-based Grouping | 将 token 数量相近的请求分到同一组 |
| 超时阈值 | Timeout Threshold | 等待时间达到阈值时，即使未满也立即开始批处理 |
| 桶 | Bucket | 按 token 长度范围划分的组（如 0-50、50-100、100-200） |
| KV Cache | KV Cache | 存储历史 Key 和 Value 以便复用，减少重复计算 |

## 3. 技术原理 / 流程拆解

### 3.1 静态批处理的缺陷

```
游乐园排队比喻：
  静态批处理：每批固定 10 人，不满不进场
  → 等待时间：GPU 空闲浪费
  → 填充浪费：长短不一的句子填充到相同长度，无效计算多

具体问题：
  1. 预设 batch size 固定，请求不足时 GPU 空闲
  2. 不同请求的输入输出长度差异大
  3. Padding 导致大量无效计算
```

### 3.2 动态批处理的工作原理

```
请求进入队列
      ↓
调度器实时判断：
  ├─ 按长度分组：将长度相近的请求合并
  ├─ 超时触发：等待 ≥10ms 立即发送当前队列
  └─ 数量触发：达到最小批次下限也发送
      ↓
合并为批次 → GPU 并行计算 → 返回结果
```

**三种触发条件：**
| 条件 | 说明 |
|------|------|
| 时间阈值 | 如 10ms 超时，人没满也发车 |
| 数量阈值 | 达到最小 batch size 下限 |
| 长度分组 | 相近长度的请求合并，减少 padding |

### 3.3 长度分组算法

```
定义桶（bucket）范围：[50, 100, 200]（token 数）

新请求进入：
  token 数 = 78 → 离 100 最近 → 分配到 100 桶
  token 数 = 45 → 离 50 最近 → 分配到 50 桶
  token 数 = 180 → 离 200 最近 → 分配到 200 桶

桶内填充：以桶的最大长度为 padding 上限
  如 100 桶内有 [78, 92, 85] → 全部 pad 到 100
  相比 pad 到全局最长（如 200），填充量大幅减少
```

### 3.4 效果数据（英伟达 TensorRT 测试）

| 指标 | 静态批处理 | 动态批处理 | 提升倍数 |
|------|-----------|-----------|---------|
| 吞吐量 | 120 req/s | 650 req/s | ~5 倍 |
| 文生图（Stable Diffusion） | 基准 | 优化后 | ~3.2 倍 |

## 5. 避坑指南

| 注意点 | 说明 |
|--------|------|
| 超时阈值需谨慎设置 | 超低延迟场景下，阈值过高会本末倒置，增加延迟 |
| 极端长请求需单独处理 | 单独分组或拆分，避免阻塞其他请求的队列 |
| 连续内存可减少碎片 | 合并后的张量使用连续内存空间，提升显存访问效率 |
| 不是所有场景都适合 | 高并发 + 长度分布不均匀时效果最好 |

## 6. 对比与思考

### 6.1 静态 vs 动态批处理

| 对比 | 静态批处理 | 动态批处理 |
|------|-----------|-----------|
| batch size | 固定 | 动态变化 |
| 触发条件 | 必须满额 | 时间/数量/分组均可触发 |
| Padding 浪费 | 多（长短不一） | 少（按长度分组） |
| GPU 利用率 | 低（等待时空闲） | 高（弹性调度） |
| 适用场景 | 请求长度均匀时 | 高并发 + 长度不均匀时 |

## 7. 本节课思维导图

- 动态批处理
  - 静态批处理的缺陷
    - batch size 固定，GPU 空闲
    - Padding 浪费
    - 请求长度差异大
  - 动态批处理的机制
    - 实时请求分组（按长度）
    - 超时触发（≥10ms）
    - 数量触发（达到下限）
  - 长度分组算法
    - 定义桶范围 [50, 100, 200]
    - 请求分配到最近桶
    - 桶内 pad 到最大值
  - 效果：吞吐量提升 3~5 倍
  - 典型框架：vLLM、TensorRT、TGI
