## 2. 核心概念图谱

### 2.1 PEFT 基础概念

| 中文术语 | 英文术语 | 通俗解释 |
|---------|---------|---------|
| 参数高效微调 | PEFT (Parameter-Efficient Fine-Tuning) | 只调整模型**一小部分参数**来完成微调，目标是**更快 + 更省显存** |
| 全量微调 | Full Fine-Tuning | 调整模型**所有**参数，效果最好但最慢最费显存 |
| 低秩适配 | LoRA (Low-Rank Adaptation) | **目前最主流的 PEFT 方法**，通过把大矩阵拆成两个小矩阵来减少训练量 |
| 秩 | Rank | 矩阵中"真正独立的信息量"有多少，**秩越小 → 矩阵越小 → 训练越快** |
| 低秩 | Low Rank | 矩阵的信息量很少（重复多），可以用很小的矩阵来近似表示 |
| 增量权重 | Delta Weight (ΔW) | LoRA 训练出来的"差值"，加到原始权重上就是微调后的结果 |
| 适配器 | Adapter | 像变色龙一样"适应"——在原始模型上追加一个**可训练的小模块**，不改原始参数 |
| 全连接层 / 投影 | Projection (QKV 等) | Transformer 里的矩阵相乘操作，把向量从一个空间映射到另一个空间 |
| 奇异值分解 | SVD | 把一个矩阵拆成三个矩阵相乘，中间那个矩阵对角线上的值叫**奇异值**，代表各维度的重要性 |
| 过拟合 | Overfitting | 模型死记硬背了训练数据，但没学到真正规律，换新数据就错 |

### 2.2 LoRA 参数概念

| 参数名 | 作用 | 老师推荐值 |
|--------|------|-----------|
| **r（Rank）** | 降到多少维。**r=16 就是让矩阵只有 16 个独立维度** | 从 8 或 16 开始试 |
| **target_modules** | 对 Transformer 的哪些层加 LoRA（Q/K/V/O 等） | Q 和 V **最有效**（论文结论） |
| **lora_alpha** | 控制 LoRA 的影响力度，乘在 ΔW 上 | 默认 16，越大效果越猛但容易过拟合 |
| **lora_dropout** | 训练时随机丢一些数据防过拟合 | **数据少才用**，0.01~0.1 |
| **use_rslora** | 是否让 alpha 除以 sqrt(r)，更精细 | 默认 False，True 更精细但更慢 |
| **loftq** | 用更好的方法初始化 LoRA 矩阵，加速训练 | 默认关闭，开启可能加速但本身耗时间 |

### 2.3 LoRA 改进变体

| 变体 | 改进点 | 一句话 |
|------|--------|--------|
| **RSLoRA** | delta_weight = alpha × A×B / sqrt(r) | 步子更小更精确，但也更慢 |
| **AdaLoRA** | 不同层/不同矩阵用**不同的 r**（动态分配） | 重要的层给大 r，不重要的给小 r，更高效 |
| **LongLoRA** | 用 local attention 扩展上下文长度 | 7B 模型从 4K 扩展到 100K 上下文 |

## 3. 技术原理 / 流程拆解

### 3.1 为什么微调需要 GPU？

```
用 API（如通义千问网页版）：
  你的代码 → HTTP 请求 → 阿里的 GPU → 返回结果
                              ↑
                        你不需要自己买 GPU

微调（自己掌控模型）：
  你的代码 → 你自己的 GPU → 你改模型参数 → 你部署服务
              ↑
        必须自己搞 GPU，因为要改模型参数
```

**用云 GPU 的两个理由：**
1. **便宜**：买一张 32G 显卡 ≈ 2 万元，租云 GPU ≈ 3.6 元/小时，学完 50 块钱搞定
2. **标准化**：云服务商的环境是主流环境（Linux + 主流框架），未来跟别人合作环境一致

### 3.2 神经网络训练的本质（400 行 C 代码讲清楚）

```
你折腾了半天微调，最后到底得到了什么？
答：就是一堆 float 浮点数！

训练前：随机 float             训练后：有意义的 float
  [0.12, 0.87, -0.33, ...]    [0.85, 0.12, -0.67, ...]
    ↑                                  ↑
  啥也不是                          能回答你的问题了

总结：
  输入层 ── 正向传播 ──→ 算 loss ── 反向传播 ──→ update weight
                                                    ↓
                                              改一堆 float
```

**C 代码演示（无框架，纯手写 400 行神经网络）**：
老师用了一个最简单的 4 层神经网络（2→4→4→1 个神经元），训练它做**异或（XOR）运算**：
```
输入：[0,0] → 输出 0
输入：[0,1] → 输出 1
输入：[1,0] → 输出 1
输入：[1,1] → 输出 0
```
训练 2000 轮后，它学会了。最后到底改了啥？就是改了一堆 `layer->neurons->outputWeights`，**其实就是一堆 float 数组**。

> **⭐ 核心道理**：不管你把神经网络包装得多复杂，Transformer 也好、扩散模型也好，最后存在模型里的就是一堆数。微调就是"把这堆数改一改，让它能回答你的问题"。

### 3.3 数字怎么存储"理解"— 词嵌入示例

**问题**：一个数字（如 0.85）怎么能代表对"苹果"这个词的理解？

**老师的三步法**：

```
假设中文只有三个词：苹果、番茄、瓜子
我要让模型理解三个维度：是不是水果、甜不甜、含水量高不高

第一步：输入编码（把词变成数字 ID）
  苹果 → [1, 0, 0]  （one-hot 编码）
  番茄 → [0, 1, 0]
  瓜子 → [0, 0, 1]

第二步：输出编码（把"理解"变成数字）
         是水果    甜度    含水量
  苹果 →  [0.999,   0.6,    0.5]
  番茄 →  [0.997,   0.75,   0.85]
  瓜子 →  [0.001,   0.03,   0.1]

第三步：求一个矩阵 W，让 输入 × W = 输出
  [1,0,0] × W = [0.999, 0.6, 0.5]
  [0,1,0] × W = [0.997, 0.75, 0.85]
  [0,0,1] × W = [0.001, 0.03, 0.1]

训练就是：不断试 W 里的数，让 输入×W 的结果越来越接近上面的输出
```

> 这样训练出来的 W（一堆 float），就存储了对这三个词的"理解"。把维度从 3 扩展到几千，词从 3 扩展到几万，就是大模型。

### 3.4 为什么不用直接解方程组？

```
问：这不就是初中数学的线性方程组吗？为什么不直接解方程求 W？

答：因为样本永远有限，但你要回答的问题无穷多。

直接解 → 得到一个"硬折线"，只拟合了已知点，泛化能力差（过拟合）
神经网络 → 得到一个"柔和曲线"，学到了内在趋势，能回答没见过的问题
```

### 3.5 LoRA 核心原理——先降维再恢复

```
┌──────────────────────────────────────────────┐
│                  原始模型                      │
│  输入 X → [ 超大矩阵 W (比如 4096×4096) ] → 输出 │
└──────────────────────────────────────────────┘

全量微调：直接改 W 的 4096×4096 = 1678 万个参数

LoRA 的做法：
  不改 W，在旁边加两个小矩阵 A 和 B
  A 是 4096×r，B 是 r×4096（r 很小，比如 16）

  输出 = X × W + X × B × A
              ↑            ↑
         原始计算     LoRA 的"增量修正"

  你只需要训练 A 和 B（4096×16 + 16×4096 = 131,072 个参数）
  是原来的 0.78%！
```

**图示理解（老师原文）：**

```
原来要找 10 个躲猫猫的小朋友（全量微调）
→ 极其费劲，得把整个小区翻个底朝天

LoRA 的做法：
→ 先缩小到 2 个人（降维到 r=2）
→ 在这 2 个人上训练（改这 2 个人的想法）
→ 再把结果还原（这 2 个人的想法扩散回 10 个人）
→ 跟原来 10 个人的想法加在一起 → 搞定

你只找了 2 个人，当然又快又省力！
```

### 3.6 LoRA 的数学本质

```
全量微调要学：ΔW（跟 W 一样大的矩阵）
LoRA 把 ΔW 分解成：ΔW = B × A × alpha
  B 是 d×r 的矩阵（竖着）
  A 是 r×d 的矩阵（横着）
  B×A 乘出来是 d×d（跟 ΔW 一样大）

因为 r ≪ d，所以 B 和 A 的参数远少于 ΔW

例：d=4096, r=16
  ΔW 参数量：4096×4096 = 16,777,216
  B+A 参数量：4096×16 + 16×4096 = 131,072
  节省了 128 倍！
```

### 3.7 为什么微调能降秩，但原始模型不能？

```
原始模型训练：用了 15T token（整个互联网的数据）
  → 信息量巨大 → 必须用全秩（大矩阵）才能容纳
  → 所以不能降秩

微调：只用 300~3000 条数据
  → 信息量很小 → 用低秩矩阵就足够了
  → 降秩理所当然

老师原话："多大屁股穿多大裤衩"
```

### 3.8 LoRA 参数详解

```
from unsloth import FastLanguageModel

model = FastLanguageModel.get_peft_model(
    model,
    r = 16,                # ⭐ 秩：降到多少维
    target_modules = [     # ⭐ 对哪些层加 LoRA
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_alpha = 16,       # ⭐ 影响力度（越大越猛）
    lora_dropout = 0,      # ⭐ 丢数据防过拟合（数据少才用）
    use_rslora = False,    # alpha 要不要除以 sqrt(r)
    loftq_config = {},     # 是否用 LoftQ 初始化
)
```

**逐个参数讲清楚：**

| 参数 | 老师原话 | 怎么调 |
|------|---------|--------|
| **r=16** | "R 就是秩，降到 16。16×16 才 256 个参数，肯定快" | 从 8 或 16 开始试。16 能搞定就 16，搞不定升 32 |
| **target_modules** | "Q 和 V 是作者实验出来最有效的，显卡不够留这两个就行" | 默认用 QKV + O + gate/up/down |
| **lora_alpha=16** | "越大影响越大，步子迈大了容易过拟合" | 通常跟 r 一样（如 r=16 则 alpha=16） |
| **lora_dropout=0** | "默认不丢。**数据越少才越需要丢**，不是越多越丢" | 数据太少（几十条）设 0.01~0.1 |
| **use_rslora** | "除以 sqrt(r) 后步子更小更精确，但也更慢" | 默认 False，需要更精细时开 |
| **loftq** | "花时间初始化，可能让训练变快，也可能不" | 默认不开 |

> **关于 dropout 的反直觉结论**：大家第一反应都是数据越多越需要丢 → 老师说他曾经也这么想 → **答案是反的：数据越少才越需要丢！** 因为数据少才容易过拟合，丢数据是为了强迫模型在少的数据上还能泛化。

### 3.9 LoRA 的优势

```
1. 参数少 → 省显存（可能只用别人一半的显存）
2. 参数少 → 算得快（训练速度快几十倍）
3. 可分离组合 → 不同 LoRA 可以叠加
4. 可合并 → 微调完可以合并回原模型（变成新的大模型文件）
5. 精度损失可忽略（甚至有时比全量微调还好！）
```

**LoRA 可以叠加（画图场景的例子）**：
```
LoRA #1: 中国风（画出来的人都穿旗袍唐装）
LoRA #2: 马尾辫（画出来的人都是马尾辫）
→ 两个 LoRA 叠在一起 → 穿旗袍的马尾辫人物

原理：两个 ΔW 各自相加，互不干扰
```

**LoRA 精度对比（来自原始论文）**：

| 方法 | 可训练参数 | 准确率 |
|------|-----------|--------|
| 全量微调（GPT-3 175B） | 175B（全部） | **最高（基准）** |
| LoRA（r=8） | 4.7M | 接近全量微调 |
| LoRA（r=64） | 37.7M | **反超全量微调** |

> 为什么 r=64 的 LoRA 反超全量微调？老师猜测："降秩降到奇异值分解时，刚好抓住了矩阵里最有代表性的几个方向，比大海捞针的全量微调找到得更准"

// 核心结构体（约 400 行 C 代码）

### 5.2 LoRA 参数避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| dropout 该不该开？ | 直觉是"数据越多越丢" | **反直觉：数据越少越需要丢！** 默认不开 |
| r 太大 | 设成 4096 就退化成全量微调了 | r 从 8 或 16 开始试 |
| 忘开 use_rslora | 默认 False | 如果效果不够精细就开启 |
| 多个 LoRA 叠加冲突 | 两个 LoRA 改了同一层参数 | 训练得好的话可以叠加，但可能互相打架 |
| LoftQ 没用对 | 花了额外时间初始化但效果没提升 | 默认不开，需要时再试 |

### 5.3 原理理解避坑

| 误区 | 正确理解 |
|------|---------|
| "LoRA 是对部分参数微调" | **不是**。LoRA 对全部参数都做了微调，只不过把计算量降下来了 |
| "降秩会丢失精度" | 理论上会，但实际选对参数 (r) 后精度损失可忽略，甚至可能反超 |
| "原始模型也能降秩" | **不能**。原始模型有 15T 的训练数据，信息量巨大，降秩装不下 |
| "参数越多效果越好" | 看情况。**"多大屁股穿多大裤衩"**，参数要跟信息量匹配 |
| "矩阵=矩阵" | 神经网络里存的是**张量（Tensor）**，矩阵是二维特例 |

### 5.4 老师经验总结

1. **"理解神经网络在干嘛，它就是在改一堆 float"** — 这个认知是理解 LoRA 的基石
2. **"降秩的本质就是让参数量跟信息量匹配"** — 数据少就用小矩阵，天经地义
3. **"从 8 或 16 开始试 r，够用就行"** — 不要一开始就上大的
4. **"Q 和 V 最有效，作者说的，我也不知道为什么"** — 实验结论
5. **"LoRA 的参数初始化很关键，LoftQ 是种更好的初始化方式"** — 但默认不开
6. **"合并在 LoRA 上很简单 — 最后把 A×B 算出来加到 W 上"** — 合并后就是一个新的大模型文件

## 6. 对比与思考

### 6.1 全量微调 vs LoRA

| 维度 | 全量微调 | **LoRA ** |
|------|---------|-----------|
| **改的参数** | 全部（175B 全改） | 极少（4.7M~37.7M） |
| **训练速度** | 慢（数十小时~数天） | **快**（几分钟~几小时） |
| **显存占用** | 高（撑爆消费卡） | **低**（一张 V100 就能跑） |
| **精度** | 最高（基准） | 接近全量，有时反超 |
| **可组合性** | 不能 | **可以叠加**多个 LoRA |
| **参数量** | 175B | 4.7M（r=8）→ 缩小 3.7 万倍 |
| **适用数据** | 大中小均可 | **小到中等数据量（300~3000条）** |

### 6.2 LoRA 变体对比

| 变体 | 改进 | 优点 | 缺点 |
|------|------|------|------|
| **原始 LoRA** | 所有层用相同的 r | 简单、稳定 | 不够精细 |
| **RSLoRA** | alpha 除以 sqrt(r) | 步子更小更精确 | 训练更慢 |
| **AdaLoRA** | 不同层动态分配不同 r | 重要层大 r，不重要的给小 r | 实现复杂 |
| **LongLoRA** | 用 local attention 扩展上下文 | 7B 模型扩展到 100K 上下文 | 已经过时（Unsloth 有更好的方案） |

### 6.3 LoRA 的本质总结

```
全量微调：你要从 8B（80 亿）个参数里，找到需要改的那几千个
          好比在 80 亿人里找你要找的几个人 → 大海捞针

LoRA：     先降维到 r=16（16 × 16 = 256 个参数）
          在这 256 个参数里训练
          最后把结果还原回去加在原始模型上
          好比先把 80 亿人缩成 256 人 → 再在这 256 人里找 → 快！

为什么能降？因为你的数据量（300 条）只配用这么小的矩阵
为什么原始模型不能降？因为人家有 15T 的数据
```

### 6.4 课后思考与延伸

1. **下节课预告（量化）**：
   - 模型量化原理
   - 训练时量化和推理时量化的区别
   - QLoRA（量化 + LoRA 组合）

2. **LoRA 为什么能超越全量微调精度？**
   - 老师个人观点：奇异值分解抓住了矩阵里最有代表性的方向
   - 你可以在实践中试试对比

3. **如何判断 r 够不够？**
   - 训练完发现"记住这个就忘了那个"→ r 太小了，升
   - 训练完效果满意 → r 够了

4. **面试导向**：
   - LoRA 原理是高频面试题
   - 说清楚"低秩分解 + 相加"就算合格
   - 能说出 Q、V 最有效是加分项
