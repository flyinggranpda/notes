## 2. 核心概念图谱

### 2.1 原生多模态概念

| 中文术语 | 英文术语 | 通俗解释 |
|---------|---------|---------|
| 原生多模态 | Native Multimodal | 模型从出生（训练开始）就接受多种模态输入，不是后期拼接的 |
| 后天拼接多模态 | Stitched/Accord Multimodal | 先用独立模块处理不同模态，然后拼到一起 |
| 视觉 Transformer | VIT (Vision Transformer) | 把图像切分成 patch，用 Transformer 处理，取代 CNN |
| Patch | Patch | 把一张图切成一个个小方块（如 16×16 像素），等同文字的 token |
| 文生图 | Text-to-Image | 给文字描述，生成图像 |
| 扩散模型 | Diffusion Model | 当前最主流的图像生成方法，从噪声逐步还原为图像 |
| 潜在扩散 | Latent Diffusion | 在压缩后的向量空间里做扩散，速度更快（Stable Diffusion） |

### 2.2 多模态模型架构分类

| 类型 | 代表模型 | 特点 |
|------|---------|------|
| **VIT 类** | Qwen-VL, LLaVA, DeepSeek-VL | 用 Transformer 替代 CNN 处理图像，与语言模型在同一架构下 |
| **原生多模态** | GPT-4o, LLaMA 4 | 一个模型**从训练开始就处理多种模态**，输入输出都能混合 |
| **Stitched 拼接** | 早期多模态模型 | 图像编码器 + 文字编码器各自独立，最后拼接 |
| **扩散模型** | Stable Diffusion, DALL-E | 专注于图像**生成**，不是理解 |

## 3. 技术原理 / 流程拆解

### 3.1 上节课尾巴：多模态 LoRA 微调

**多模态 LoRA 微调 vs 纯语言 LoRA 微调：只有两处不同**

```
不同点 1：需要装 torchvision
  pip install torchvision==0.21  # 版本必须与 torch 版本对应

不同点 2：数据集里包含 image 字段
  纯语言：{"text": "...", "output": "..."}
  多模态：{"image": "<图片路径>", "text": "...", "output": "..."}
```

**完整流程回顾：**

```python
# 跟之前的微调完全一样，只是模型变成多模态的
from unsloth import FastLanguageModel
from transformers import AutoProcessor

# Step 1: 加载多模态基座模型（如 Qwen2.5-7B-VL）
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-7B-VL",
    load_in_4bit=True,
)

# Step 2: 配置 LoRA（跟之前一模一样）
model = FastLanguageModel.get_peft_model(model, r=16)

# Step 3: 加载数据集（输入是 image + text）
dataset = load_dataset("your_multimodal_dataset")
# 数据集长这样：
# {"image": "...", "text": "Write the LaTeX for this equation"}

# Step 4: 训练、保存 —— 跟之前完全一样！
```

**老师课上演示的案例**：用通义千问 2.5-7B-VL 微调，把图片里的数学公式转成 LaTeX 代码

```
微调前：模型乱写 LaTeX，编译报错（幻觉）
微调后：模型输出合法 LaTeX，可以用 Python 渲染成正确的数学公式

训练时间：仅 2 分钟！
数据集：6 万条（图片 → LaTeX 代码）
```

### 3.2 什么是 Native Multimodal（原生多模态）

```
Native（原生） vs Accord（后天习得）:

原生：模型天生（从训练开始）就能处理多种模态
后天：模型先学会一种模态，再拼接另一种

类比：
  原生多模态 = 双语家庭长大 → 两种语言都 native
  拼接多模态 = 先学英语，大学再学法语 → 后天习得
```

**大厂对原生多模态的定义：**

```
GPT-4o（OpenAI，2024年5月发布）：
  "第一个原生多模态模型"
  输入：任意组合的文字/音频/图像/视频
  输出：任意组合的文字/音频/图像

LLaMA 4（Meta，2025年4月发布）：
  "开启了原生多模态的新纪元"

共同点：一个模型处理所有模态，不需要独立模块拼接
```

**判断一个模型是否原生多模态：**
```
看它训练时是否同时处理了多种模态：

VIT + LLM（如 Qwen-VL）：
  图像用 VIT 编码 → 文字用 LLM 处理 → 拼接
  训练时分开训练的 → 不是原生

GPT-4o：
  从训练第一天起，就是图像+文字+音频一起训练
  同一个 Transformer 处理所有模态 → 是原生
```

**原生多模态的意义：**
```
不同模态之间不是"翻译"关系，而是"共生"关系

原生模型看到一个苹果的图片时，
它理解的不只是"这是一个苹果"，
而是图像中的苹果 + "apple"这个词 + 苹果的声音
都在同一个向量空间里 → 理解更深
```

### 3.3 Vision Transformer (VIT)

```
VIT 的核心思想：把图像当成文字来对待

文字的处理：
  "你好吗" → [token, token, token] → Transformer

VIT 的做法：
  一张图片 → 切成 16×16 的 patch → 每个 patch = 一个"视觉 token"
  → [patch_token, patch_token, ...] → Transformer
```

**VIT vs CNN 的核心区别：**

```
CNN：
  用卷积核逐层提取特征
  从边缘 → 形状 → 物体
  局部到全局，层层递进

VIT：
  把图切成 patch，所有 patch 一次送入 Transformer
  Self-Attention 直接让每个 patch 跟所有其他 patch 算关系
  从一开始就是全局的
```

**VIT 的优势：**
```
CNN 依赖"局部性假设"——相邻像素才有关联
VIT 没有这个假设——远处的 patch 也能直接交互
→ 对全局关系的理解更好
→ 在大规模数据上 VIT 效果超越 CNN
```

### 3.4 多模态模型的两大阵营（理解 vs 生成）

```
多模态任务分两大类：

一、理解类（输入非文字，输出文字）
  VQA：图片 → 文字回答
  图生文：图片 → 文字描述
  文档问答：发票 → 提取金额
  —— 上节课+本节课上半部分内容

二、生成类（输入文字，输出非文字）
  文生图："一只猫在沙滩上" → 图片
  文生视频："A dog barking" → 视频
  文生音乐：歌词 → 音乐
  —— 本节课下半部分内容
```

### 3.5 扩散模型（Diffusion Model）— 图像生成的核心

```
扩散模型原理（简化版）：

训练阶段：
  清晰图片 → 逐步加噪声 → 变成纯噪声
                          ↓
                    学习"如何逆向去噪"

生成阶段：
  纯噪声 → 逐步去噪 → 得到清晰图片
```

```
正向扩散过程（训练时）：
  原图 → 加一点点噪声 → 再加一点 → ... → 全是噪声
  x₀    → x₁          → x₂       → ... → x_T

逆向扩散过程（生成时）：
  噪声 → 预测噪声并去除 → 再去除 → ... → 生成图片
  x_T  → x_{T-1}       → x_{T-2} → ... → x₀
```

**潜在扩散（Latent Diffusion）：**
```
直接在像素空间做扩散太慢（图片太大）
→ 先用 VAE 把图片压缩到"潜在空间"（latent space）
→ 在压缩后的空间做扩散
→ 最后用 VAE 解码器还原成图片

这就是 Stable Diffusion 的核心架构！
```

### 3.6 复杂数学推理的实现思路

**老师对学生问题的回答：**

```
Q：如何让大模型拥有真正的数理逻辑推理能力？
A：坦白说，我觉得做不到。但很多模型"显得"能做到，
   是通过以下方式：

1. 用支持思维链（Chain-of-Thought）的基座模型
2. 准备需要"一步一步推理"的微调数据
   例："(10÷2)+3=?" 不要直接给答案"8"
       要标注成 "10÷2=5 → 5+3=8"
3. 模型在微调中学会了"解题步骤"的 pattern
   但它不是真正在"理解数学"，而是在模仿解题模式

注意：如果基座模型本身不具备某种逻辑能力，
      通过 100 或 1000 条数据微调是调不出来的。
```

### 4.1 案例一：多模态 LoRA 微调（图片→LaTeX）

- **教学目的**：展示多模态模型的微调和纯语言模型几乎一样
- **要回答的核心问题**：多模态微调到底多了什么？

**任务**：给一张数学公式的图片，让模型输出对应的 LaTeX 代码

```python
# 安装（多一个依赖）
pip install torchvision==0.21  # 版本必须匹配 torch

# 加载多模态基座模型
from unsloth import FastLanguageModel
model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="Qwen/Qwen2.5-7B-VL",  # 多模态版！不是纯语言版
    load_in_4bit=True,
)

# 加载 LoRA 适配器（跟之前完全一样）
model = FastLanguageModel.get_peft_model(model, r=16)

# 加载数据集（图像+文字，跟纯语言不同）
from datasets import load_dataset
dataset = load_dataset("your/latex_ocr_dataset")
# 数据长这样：
# {
#   "image": <PIL Image>,       # 数学公式图片
#   "text": "Write the LaTeX representation for this image"
# }
# 训练：2 分钟
# 效果：微调前输出不合法，微调后能输出正确 LaTeX
```

**多模态微调 vs 纯语言微调对比：**

| 维度 | 纯语言 LoRA | 多模态 LoRA |
|------|------------|------------|
| 基座模型 | Qwen2.5-7B | **Qwen2.5-7B-VL**（多模态版） |
| 额外依赖 | 无 | **torchvision**（处理图像） |
| 数据集格式 | `{text, output}` | `{image, text, output}` |
| LoRA 配置 | 一样 | **一样** |
| 训练代码 | 一样 | **一样** |
| 推理输入 | text | **image + text** |

### 4.2 案例二：原生多模态 vs 拼接多模态的思想实验

- **教学目的**：理解"原生"和"拼接"的区别
- **要回答的核心问题**：为什么原生多模态更好？

```
假设你在学"苹果"这个概念：

拼接多模态：
  先单独学文字："apple = 一种水果"
  再单独学图像：[苹果图片的特征向量]
  最后把两个向量拼在一起
  → 两个模态是"翻译关系"

原生多模态：
  从一开始，文字"apple"和苹果图片同时输入
  同一个 Transformer 处理两者
  模型自己发现"文字里的 apple"和"图像里的红色圆形"是同一个概念
  → 两个模态是"共生关系"
```

### 4.3 案例三：VIT 理解

- **教学目的**：理解 VIT 的核心工作方式
- **要回答的核心问题**：Transformer 怎么处理图像？

```
VIT 的工作流程：

原始图片（224×224×3）
    ↓ 切成 16×16 的 patch
196 个 patch（14×14 网格，每个 16×16 像素）
    ↓ 每个 patch 展平 + 线性投影
196 个向量（每个 768 维）← "视觉 token"
    ↓ 加上位置编码
196 个带位置信息的向量
    ↓ 送入 Transformer Encoder
    ↓ Self-Attention 让每个 patch 跟所有其他 patch 交互
输出：理解后的图像表示
```

## 5. 避坑指南（隐性知识提取）

### 5.1 多模态安装避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| torchvision 装不上 | 版本不匹配 | 先 `pip show torch` 看版本，再去官网查对应的 torchvision 版本 |
| Unsloth 不支持某些多模态模型 | 需要等几天 | 新模型发布后 Unsloth 一般 3 天内支持 |
| 多模态推理慢 | 图像处理消耗大 | 离线处理，不要实时 |
| 数据集太大下载慢 | 多模态数据集常含大量图片 | 提前下载，用 `dataset.save_to_disk()` |

### 5.2 原生 vs 非原生避坑

| 误区 | 事实 |
|------|------|
| "VIT + LLM = 原生多模态" | ❌ 不是，这是拼接的。原生是**从训练开始**就多模态 |
| "原生多模态 = 效果一定好" | 不一定，但理论上更优（共生 vs 翻译） |
| "开源多模态模型都落后" | 开源在快速追赶，Qwen-VL、LLaVA 都很强 |

### 5.3 扩散模型避坑

| 问题 | 原因 | 建议 |
|------|------|------|
| 生成图片崩坏 | 扩散步数不够 | 增加采样步数（如从 20 步到 50 步） |
| 图片不符合描述 | Prompt 写得不够好 | 学会写 Prompt（提示词工程在文生图里很重要） |
| 生成太慢 | 像素空间太大 | 使用潜在扩散（Latent Diffusion） |

### 5.4 老师经验总结

1. **"多模态微调和纯语言微调几乎一样"** — 就多了 torchvision 和数据集里的 image 字段
2. **"原生多模态 = 不同模态是共生不是翻译"** — 这是下一代模型的方向
3. **"模型不是真正理解数学，它只是在模仿解题步骤"** — 思维链的真相
4. **"100 或 1000 条微调数据，调不出基座模型本身没有的能力"** — 微调不能无中生有
5. **"下节课开始全是实战项目，没有理论了"** — 课程进入下半场

## 6. 对比与思考

### 6.1 VIT vs CNN

| 维度 | CNN | VIT（Vision Transformer） |
|------|-----|--------------------------|
| 核心操作 | 卷积（局部） | Self-Attention（全局） |
| 对局部性的依赖 | **强**（相邻像素才有意义） | 弱（patch 间都能交互） |
| 图像处理方式 | 层层递进提取特征 | 切 patch + 一次性全局处理 |
| 小数据量效果 | **好** | 差（需要大量数据） |
| 大数据量效果 | 一般 | **好**（超越 CNN） |
| 发展趋势 | 逐渐被取代 | **主流方向** |

### 6.2 理解类 vs 生成类多模态

| 维度 | 理解类（VQA/图生文） | 生成类（文生图/视频） |
|------|-------------------|-------------------|
| 输入→输出 | 图像→文字 | 文字→图像 |
| 核心模型 | VIT + LLM | **扩散模型** |
| 代表产品 | GPT-4o（理解） | Stable Diffusion, DALL-E |
| 成熟度 | 较高 | 中等（仍不完美） |
| 难度 | 中等 | 高 |

### 6.3 原生多模态 vs 拼接多模态

| 维度 | 拼接（Stitched） | 原生（Native） |
|------|----------------|---------------|
| 训练方式 | 各模态独立训练后拼接 | **一个模型从头训练所有模态** |
| 模态关系 | 翻译关系 | **共生关系** |
| 效果理论 | 上限较低 | 上限高 |
| 代表模型 | Qwen-VL, LLaVA | **GPT-4o, LLaMA 4** |
| 训练成本 | 低 | 极高 |
| 当前状态 | 开源主流 | 闭源为主，Meta/OpenAI 垄断 |
